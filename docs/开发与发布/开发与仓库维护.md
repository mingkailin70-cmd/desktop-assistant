更新：2026-10-08。GitHub远端为 mingkailin70-cmd/desktop-assistant，分支 main；本地工作目录由开发者自定。用户要求每完成一个阶段形成提交并推送；不强推、不重写已发布历史。仓库设置清单见[GitHub仓库设置清单](../仓库管理/GitHub仓库设置清单.md)。

## 固定约束

- .NET SDK 固定为 10.0.401，global.json 禁止自动漂移；本机 SDK 放在已忽略的 .tools 目录。
- 浏览器切片新增锁定的 NuGet 运行时依赖 `Microsoft.Playwright` 1.63.0（MIT）及其精确传递依赖；`PlaywrightPlatform=win-x64` 令发布包只携带 Windows x64 Node 驱动，Edge Stable 仍由系统提供。Windows SDK targeting pack `Microsoft.Windows.SDK.NET.Ref` 固定为 10.0.26100.87，已获准下载并在本机缓存。Windows 任务库调用系统 `winsqlite3.dll`；本机观察到版本 3.51.1，当前实现要求至少 3.31.0，其他 Windows 版本的 DLL 版本/ABI 尚未验收。Host 的 Windows SDK 引用版本精确固定，NuGet 锁文件锁定普通依赖图。用户已授权首版 Qwen 主模型、ASR、TTS 和 MiMo 9B 权重仅下载到仓库忽略的 `models/`，并批准下载 llama.cpp b11259 CUDA 13.4 资产；资产已校验及暂存；用户已确认 CUDA 本机许可，两次合成推理通过，资源与质量仍待验收。Python 语音环境和依赖已安装并锁定；用户已授权本项目后续所需依赖、运行时和候选模型资产直接下载及执行必要联网命令，无需逐项询问，仍须核对来源、许可和哈希。
- 不将模型、缓存、数据库、日志、录音、截图、通知正文、凭证和本机设置提交到 Git。
- Windows桌面交互由当前用户进程负责；模型只产出结构化提案，ToolBroker决定权限与执行。
- 每个阶段结束先看差异/编译结果和数据忽略规则，再创建阶段提交并推送到指定远端。

## 工程模块

- XiaoK.Host：桌宠、托盘、快捷键、文字输入、任务状态、取消和审批预览。
- XiaoK.Core：任务、工具、消息通知与审批契约。
- XiaoK.Tools：固定工具注册与调用协调。
- XiaoK.Adapters.Windows：应用启动、文件检索、窗口核验及消息适配器。
- 本机文件分类采用 `XiaoK.Adapters.Windows` 中的句柄式只读枚举；分类表/范围策略在 Core，边界见[本机文件分类边界](../架构与接口/本机文件分类边界.md)。
- XiaoK.Adapters.Browser：只读静态公开网页读取；使用独立无头 Edge，不接管用户浏览会话。
- XiaoK.Inference：本机回环模型客户端和排他资源租约。
- XiaoK.Voice：唤醒、VAD、ASR、TTS边界。
- XiaoK.Storage：Windows 系统 SQLite 脱敏任务状态、固定联系人风格偏好、固定字段审批审计、旧任务/设置迁移、一致性备份/恢复与带迁移标记保护的个人记录清理。设置页已有只读审批历史、数据库备份/恢复和清理入口；清理还会尝试截断 WAL、VACUUM，并仅删除识别出的小K旧源和备份文件。审批记录不保存预览内容或路径。评测样本数据库化、真实用户数据恢复/清理演练和存储介质级擦除保证仍待完成。

个人运行数据放在 `D:\XiaoK\Data`；开发仓库模型副本仍放在根目录 `models/`（实际路径 `D:\Desktop\learn\siri\models`），该目录已被 Git 忽略且不得提交。正式运行模型已部署到 `D:\XiaoK\Models`，语音运行环境位于 `D:\XiaoK\Voice`；部署的文件数、散列、离线依赖和 CPU 合成往返证据见[本机 D 盘运行环境部署核验](../验收与评测/D盘本地运行环境部署核验.md)。缓存与用户数据放 D 盘仓库外目录。Windows用户设置位于 `%LOCALAPPDATA%\XiaoK\settings.json`。

## 本地命令

单文件 ZIP 压缩专项安全检查使用合成夹具运行：

    .\.tools\dotnet\dotnet.exe run --project tests\XiaoK.Tools.SafetyChecks\XiaoK.Tools.SafetyChecks.csproj --configuration Release --no-build --no-restore -- --only-file-archive

本仓库通过 `global.json` 使用本机 `.tools\dotnet\dotnet.exe`（SDK 10.0.401）；若该副本不存在，再使用系统中固定版本的 `dotnet`。

    .\.tools\dotnet\dotnet.exe --version
    .\.tools\dotnet\dotnet.exe restore XiaoK.sln --locked-mode
    .\.tools\dotnet\dotnet.exe build XiaoK.sln --configuration Release --no-restore
    .\.tools\dotnet\dotnet.exe run --project tests\XiaoK.Tools.SafetyChecks\XiaoK.Tools.SafetyChecks.csproj --configuration Release --no-build --no-restore
    .\.tools\dotnet\dotnet.exe .\tests\XiaoK.Tools.SafetyChecks\bin\Release\net10.0\XiaoK.Tools.SafetyChecks.dll --only-file-classification
    .\.tools\dotnet\dotnet.exe run --project src\XiaoK.Host\XiaoK.Host.csproj --configuration Release --no-build --no-restore

桌面窗口的开发版也可直接由仓库内运行时加载 Host 程序集，避免双击 apphost 时依赖系统级 .NET 安装：

    .\.tools\dotnet\dotnet.exe .\src\XiaoK.Host\bin\Release\net10.0-windows10.0.26100.0\XiaoK.Host.dll
    .\.tools\dotnet\dotnet.exe .\src\XiaoK.Host\bin\Release\net10.0-windows10.0.26100.0\XiaoK.Host.dll --diagnostics-profile

普通运行会按默认设置在仓库外创建 `D:\XiaoK\Data`；开发版新设置默认把模型根目录指向仓库忽略的 `models/`，MSIX 安装实例使用 D 盘正式目录。小K桌宠窗口显示在任务栏，便于从 Windows 窗口列表定位；托盘菜单仍提供显示桌宠、打开任务面板、停麦、取消和退出。开发版窗口已在本机 Open Computer Use 枚举中出现；已安装版桌宠与展开任务面板已目视检查。多屏、不同桌面背景透明边缘与完整长期视觉验收仍待完成。MSIX 使用 win-x64 自包含发布，不能假设用户机器预装系统级 .NET。

只做视觉和控件检查时使用 `--diagnostics-profile`：它创建唯一 `%TEMP%\XiaoK-Diagnostics-<随机ID>` 配置，设置、SQLite、隔离目录和恢复清单均留在该临时配置内；不加载真实设置，不搜索用户目录，不连接模型服务，不请求通知权限，也不采集麦克风。此模式下提交任务只显示“未执行”，不会启动应用、读写项目文件或发送消息。退出后诊断目录保留，供本机检查；需要时可手动删除该随机目录。普通启动命令仍使用真实用户设置和数据，启动前必须确认正在使用哪个模式。

其他计算机请把上述命令中的本地路径替换为 `dotnet`，并安装 SDK 10.0.401。NuGet 源映射只放行明确列出的 Windows SDK、win-x64发布运行时、Playwright .NET 及其精确传递依赖。Playwright 固定1.63.0，`Directory.Build.props` 设定 `PlaywrightPlatform=win-x64`，发布包仅包含 Windows x64 Node 驱动；浏览器本体使用已安装的 Edge Stable。其隔离范围和未通过的在线探针见[公开网页静态读取边界](../架构与接口/公开网页静态读取边界.md)。本项目所需依赖、运行时及候选模型已获直接下载授权，无需逐项询问；新增资产仍须写清上游来源、版本、许可和用途，锁定散列并更新 NuGet.config/锁文件/工作流。下载授权不等于接受新许可条款；许可未知或不兼容时不得继续使用。

生成可离开系统级 .NET 运行时的 Windows x64 自包含 Release 发布目录，并校验未签名 MSIX 包结构：

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\publish_xiaok.ps1

脚本固定 SDK 10.0.401，先以 locked mode 还原 `win-x64`，再按 `Windows-x64-self-contained.pubxml` 发布到被忽略的 `artifacts\publish\win-x64`。它核验发布输出含 .NET 10.0.12 和 Windows Desktop 运行时，再调用 MakeAppx 检查包。

创建当前用户的本机开发签名证书，并生成签名 MSIX 验证包：

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\new_xiaok_dev_certificate.ps1
    $cert = Get-Content artifacts\signing\xiaok-development-certificate.json -Raw | ConvertFrom-Json
    .\tools\package_msix_validation.ps1 -CertificateThumbprint $cert.thumbprint

证书脚本创建 RSA 3072 自签名身份，私钥不可导出并留在 `Cert:\CurrentUser\My`；只将公开证书及指纹写入 Git 忽略的 `artifacts\signing`。打包脚本校验发布者、代码签名用途和有效期后，由 Windows SDK SignTool 执行 SHA-256 签名。安装脚本默认只读预检；带 `-Install` 时需管理员权限，将公钥导入 `Cert:\LocalMachine\TrustedPeople`，验签后只为当前账户安装应用，不自动启动。卸载脚本支持 `-WhatIf` 和逐步确认；单独移除机器信任前会检查全机是否还有同发布者软件包。当前账户仍安装旧版本；新生成的签名验证包需以对应阶段记录为准，签名本身不代表已安装。签名信任导入会影响本机所有账户。应用启动、Windows 授权、登录启动、重启恢复和实际回滚仍待验收。

`XiaoK.Tools.SafetyChecks` 是本地可执行安全检查套件，包含浏览器适配器锁定依赖，目前覆盖隔离编程代理、通知策略和后台文件复制、重命名；参数 `--only-tool-proposal-preconditions` 可单独运行 ToolBroker 固定前置条件与结果枚举检查，`--only-file-copy` 可单独检查限定源目录、固定导出目录、同名冲突、大小上限与SHA-256核验；参数 `--only-file-rename` 可单独检查原目录改名、同名拒绝、非法名称、搜索范围和取消路径，`--only-window-activation` 可单独运行模拟的窗口切换结果/取消路径检查，`--only-window-selection` 可验证唯一窗口句柄选择策略，`--only-app-launch` 可单独检查白名单应用的固定启动路径、项目参数、窗口核验和启动失败状态。完整套件会检查用户配置的文件搜索目录仅含已存在的本机固定盘、可移动盘或 RAM 盘，拒绝相对路径、UNC/映射网络盘、磁盘根目录和超过20项目录，并覆盖重复路径规范化；桌面应用路径策略检查固定程序文件名、文件存在和本机盘符。参数 `--without-appcontainer` 会显式跳过完整检查中的四项 AppContainer OS 边界/进程恢复检查，继续运行其余本地安全检查，并逐项输出“跳过”；它只用于诊断其他检查，不能作为隔离边界或完整 P3 通过证据。默认无参数运行仍执行全部检查，AppContainer 失败不会静默跳过。检查入口会捕获异常并返回非零退出码与堆栈；AppContainer 子探针也会把受限写入失败转为明确诊断和退出码。安全检查进程在启动时为自身及子进程设置临时 Win32 错误模式，抑制进程级 Windows 崩溃弹窗；该设置不改 Windows 全局配置，异常仍按失败状态和事件日志记录。历史 Windows 日志仍保留过去的访问拒绝/断言失败事件；这些历史记录不覆盖后续成功运行。2026-10-02 本机用户上下文默认完整套件为70项通过、0项跳过，实际检查了 AppContainer 文件边界和进程恢复。安全检查也不替代真实本地模型、微信/QQ、MSIX 或发布门槛验收。网页读取定向检查可运行 `--only-public-web-read`；`--only-browser-render` 会启动真实无头 Edge 测试静态夹具；`--probe-public-web-read https://example.com/` 会访问指定公网网页，仅输出正文字符数，不打印正文。

若受限的代理/开发沙箱在 `CreateAppContainerProfile` 阶段返回 `0x80070002`（`ERROR_FILE_NOT_FOUND`），该运行环境可能未暴露 AppContainer 配置文件能力；不得改代码静默跳过或使用普通用户权限替代。此前有一次本机完整套件记录为63项通过、0项跳过；Windows应用日志随后记录到2026-10-02 02:42的安全检查断言失败（只读代码检索没有把所选项目文件内容交给模型），因此旧的全通过记录不再代表当前状态。最新复测命令 `\.tools\dotnet\dotnet.exe build XiaoK.sln --configuration Release --no-restore` 使用固定SDK 10.0.401，构建为0警告、0错误。默认完整套件命令 `\.tools\dotnet\dotnet.exe run --project tests\XiaoK.Tools.SafetyChecks\XiaoK.Tools.SafetyChecks.csproj --configuration Release --no-build --no-restore` 在创建临时AppContainer身份时返回Win32 `-2147024894` 并以非零退出受控失败，没有普通用户权限回退，也未弹出CLR错误框。诊断命令追加 `-- --without-appcontainer` 后为65项通过、4项显式跳过，只能诊断其他检查，不能证明隔离边界通过。此前应在具备AppContainer配置文件能力的获准Windows会话中原样运行默认套件；2026-10-02在本机用户上下文原样运行默认套件得到70项通过、0项跳过，覆盖AppContainer边界和进程恢复检查。受限沙箱错误仅保留作执行环境诊断。合成探针通过不代表真实项目命令行为、模型质量或发布门槛已验收。

窗口切换的本机实测可运行 `dotnet exec tests\XiaoK.Tools.SafetyChecks\bin\Release\net10.0\XiaoK.Tools.SafetyChecks.dll --verify-live-vscode-window "D:\VS Code\Code.exe" "D:\Desktop\learn\siri"`，并按本机实际路径替换两个参数。该命令通过固定的“小K项目”意图和 ToolBroker 执行一次切换，随后独立核验目标窗口确实位于前台；只接受路径完全匹配的 `Code.exe`、包含 `XiaoK.sln` 的项目目录及唯一窗口，可能将该本地窗口置于前台。它要求在当前交互式 Windows 用户桌面运行；隔离测试桌面看不到用户窗口，返回 `WINDOW_NOT_FOUND` 不代表实机失败。

## GitHub维护

GitHub Actions 工作流在推送 `main`、PR 和手动触发时构建 Windows 解决方案；最近本地阶段提交均通过本机 Release 构建和检查。远端每次 CI 运行状态须在 GitHub Actions 页面核验，本文不保存可能过期的运行结果。Dependabot 配置仅检查 GitHub Actions 更新，不自动引入 NuGet 包。Issue/PR 模板要求不给出真实消息或凭证。仓库尚未选定许可证；公开可见不代表授予复用权限。

本机 Git 凭据可正常推送；最近一次阶段提交已推送到 `origin/main`。Git 索引/对象目录写入由受审查的 Git 操作完成，不需要放宽项目工作区权限。不得强推或重写已发布历史。遇到上传失败时保留本地提交并报告；仓库权限、分支保护等远端设置由所有者在 GitHub 页面管理。
