# 小K模型权重与环境部署方案

## 当前依赖版本核验补充（2026-09-30）

Qwen3-TTS 0.6B 官方仓库的 1.83 GB model.safetensors 外还需要 682 MB 的 speech tokenizer 权重；文件名为 speech_tokenizer/model.safetensors，上游 SHA256 为 836b7b357f5ea43e889936a3709af68dfe3751881acefe4ecf0dbd30ba571258。只取得主模型权重不能标记为可推理。

Qwen 官方依赖声明显示，ASR 的 qwen-asr 0.0.6 使用 Transformers 4.57.6，TTS 的 qwen-tts 0.1.1 使用 Transformers 4.57.3，两者依赖版本不同，因此部署为独立 Python 3.12 x64 venv。两者均声明 Accelerate 1.12.0；其余传递依赖仍需生成精确版本与哈希锁文件，不能直接使用无锁的 pip upgrade。

PyTorch 2.14.0 是当前核验到的稳定版；官方提供 Windows CPython 3.12 CUDA 13.2 wheels，与用户给出的 NVIDIA 驱动报告相符。ASR/TTS 的 PyTorch 2.14.0 + cu132 是 GPU 部署候选，不代表运行兼容性已经验收。先验证官方轮子、Qwen 推理代码和实际显存；失败时改测 CPU 或 llama.cpp 路径，不能从第三方站点取得 wheel。

语音工作进程显式使用 D 盘缓存和临时目录。下载文件完成校验后再启用离线环境：

~~~text
HF_HOME=D:\XiaoK\Cache\huggingface
HF_HUB_CACHE=D:\XiaoK\Cache\huggingface\hub
TORCH_HOME=D:\XiaoK\Cache\torch
TEMP=D:\XiaoK\Temp
TMP=D:\XiaoK\Temp
HF_HUB_OFFLINE=1
TRANSFORMERS_OFFLINE=1
~~~

依赖源：[Qwen3-ASR pyproject.toml](https://github.com/QwenLM/Qwen3-ASR/blob/main/pyproject.toml)、[Qwen3-TTS pyproject.toml](https://github.com/QwenLM/Qwen3-TTS/blob/main/pyproject.toml)、[PyTorch 2.14 官方发行说明](https://pytorch.org/blog/pytorch-2-14-release-blog/)、[PyTorch CUDA 13.2 wheel 索引](https://download.pytorch.org/whl/cu132/torch/)。

> 文档状态：Qwen3.5-4B、Qwen3-ASR-0.6B、Qwen3-TTS-12Hz-0.6B-Base 固定 revision 的20个模型/配置/分词器文件已下载至仓库忽略的 `models/`，本机 SHA256 与锁定散列全部匹配；模型总计约7.10 GB。模型效果、运行时、语音环境、GPU资源仍未验收。系统 Schannel 经代理握手失败；本机 Python OpenSSL 通过 `127.0.0.1:7897` 完成经过证书验证的 TLS 访问。
> 核验日期：2026-10-02。在线仓库可变，部署必须使用固定 revision 和本机 SHA256。
> 仓库规则：用户已授权模型权重下载到当前仓库根目录 `models/`。模型运行时、Python 环境和依赖包仍须逐项取得用户确认；未经批准不运行新的联网安装命令。

## 1. 部署目标与顺序

目标机器为 Core Ultra 9 275HX、32 GB RAM、RTX 5060 Laptop 8 GB 与 Intel 集显。桌宠和托盘长期运行；轻量唤醒模型用 CPU；LLM、ASR、TTS 按需启动并共用显存预算。

1. 主 LLM：Qwen3.5-4B，Q4_K_M GGUF + llama.cpp CUDA 后端为候选。不能满足质量或运行要求时再比较其它本地方案。
2. ASR：官方 Qwen3-ASR-0.6B Transformers 权重，独立 Python 3.12 环境；先测 CPU，再测 GPU。
3. TTS：官方 Qwen3-TTS-12Hz-0.6B-Base；按需合成，与主 LLM 共用资源锁。
4. 唤醒：sherpa-onnx 中文 KWS/VAD 小模型，CPU 常驻；需先测自定义“Hi 小K”的误唤醒和漏唤醒。
5. MiMo：MiMo-V2.6-Distill-Qwen-9B 用作可选离线评测。官方 Transformers 权重约 18.8 GB，不适合 8GB 显存常驻；仅在 CPU/部分卸载速度、RAM 与温度可接受时作为按需深度任务模型。
6. JEV：`autotrust/JEV-9B` 与 `JEV-27B` 为独立开源决策模型研究项，不是 TypeSafe Jev 官方权重。分别约18 GB和54.7 GB且上游推荐 vLLM，不列首版主模型；离线评估时只让它从确定候选中选择，执行仍须 ToolBroker。

系统不假定 Core Ultra NPU 已受推理框架支持。首版不能让 4B、9B、ASR 和 TTS 权重同时占用 GPU。

### 2.1 锁文件格式

在 model-lock/models.lock.json 维护，不存权重本身。当前已根据固定源 revision 和带完整来源说明的镜像卡登记预期文件大小/散列；下载前仍须再次复核源文件，`localVerifiedSha256` 只有在本机实际下载并校验后填写：

~~~json
{
  "schemaVersion": 1,
  "models": [
    {
      "id": "qwen3.5-4b-q4km",
      "role": "primary-llm-candidate",
      "repo": "lmstudio-community/Qwen3.5-4B-GGUF",
      "revision": "f9f88ac3e234be915e23811a6d28ea287bdb927e",
      "files": [
        {
          "name": "Qwen3.5-4B-Q4_K_M.gguf",
          "sizeBytes": 2707513696,
          "sha256": "25082a7dd3776cc3c741c6347d3bd04523f05796607b3fbc32fa3a25dfa1418c"
        }
      ],
      "baseModel": "Qwen/Qwen3.5-4B",
      "baseModelRevision": "851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a",
      "quantizer": "lmstudio-community",
      "conversionRuntime": "llama.cpp b8185",
      "license": "apache-2.0",
      "localVerifiedSha256": null,
      "verification": "待复核固定源文件；下载后本机校验并实测推理"
    }
  ]
}
~~~

不以 main/latest 单独标识部署内容。新版本下载到并行目录，校验后原子切换 current；回滚窗口内保留上一套已验收的文件。量化来源未能复核或提示输出不正确时，不采用该量化文件。

## 3. 推理后端版本与兼容性

截至 2026-10-02，llama.cpp 官方 Release 页的最新固定候选为 b11259 预发布版，源提交 `d280808f5d82fcc3142b53f94ea5f594250cd765` 有 GitHub 验证签名。Windows x64 CUDA 13.4 主程序 ZIP 与配套 DLL ZIP 的 SHA256 已从官方 GitHub 构建证明 51199980 登记。Qwen3.5-4B 官方仓库提供 Transformers Safetensors，Q4_K_M 是第三方 GGUF 量化；Hugging Face 文件卡给出固定量化文件大小和 SHA256，并声明来源 revision。模型架构及 GGUF 转换仍需在本机后端上验收，不能只依据仓库名称或社区跑分。

2026-10-02 只读快照为 Driver 596.49、NVIDIA-SMI 显示 CUDA 13.2。NVIDIA 的 CUDA 13.x minor-version compatibility 最低驱动版本为 580，596.49 在该范围内，因此 CUDA 13.4 资产可进入首测候选；这不替代实际运行测试。首轮测试 CUDA 13.4；失败时再分别评估 Vulkan 和 CPU 资产，不盲装 CUDA Toolkit 修补。获得逐项联网下载确认后再取二进制。经 P0 验收后，才把实际资产名称、SHA256、动态库清单写为锁定运行版本。

### 3.1 托管运行时清单与生命周期

`XiaoK.Inference` 已提供可选的 `LlamaCppModelRuntime`。模型下载完成、固定 revision 与 SHA256 本机校验后，清单 `llama-runtime.json` 放在模型版本目录中；llama.cpp 运行包仍须单独批准下载并复核来源、资产名、许可和 SHA256。程序只接受 schema 1、llama.cpp `b11259`、模型 ID `qwen3.5-4b-q4km`、上下文 1,024–8,192 和 GPU 层 0–99；文件固定为该版本目录下 `Runtime\llama-server.exe` 与 `Qwen3.5-4B-Q4_K_M.gguf`。权重由 `python tools/download_locked_models.py --model qwen3.5-4b-q4km --proxy http://127.0.0.1:7897` 获取；下载器核对固定 revision、上游文件大小与 SHA256，支持续传，并保留 TLS 证书校验。两个 SHA256 都必须是 64 位十六进制。本机实际文件每次进程启动前重新计算哈希，并保留禁止写入/删除的只读文件句柄。

ASR/TTS 使用同一个锁定下载器和代理参数，模型 ID 分别为 `qwen3-asr-0.6b` 与 `qwen3-tts-12hz-0.6b-base`。下载器只使用 Python 标准库；运行推理仍需另外部署获批的 Python 3.12 环境及锁定依赖。

清单示例（开发时只放在已忽略的模型 revision 目录；正式部署迁移到 D 盘对应模型目录；不提交到 Git；占位散列不可直接使用）：

~~~json
{
  "schemaVersion": 1,
  "runtimeVersion": "b11259",
  "runtimeSha256": "由官方已复核资产填写的64位SHA256",
  "modelId": "qwen3.5-4b-q4km",
  "modelSha256": "由已锁定GGUF文件填写的64位SHA256",
  "contextTokens": 4096,
  "gpuLayers": 99,
  "expectedGpuMemoryMiB": 5000
}
~~~

示例预算 `5000` 只用于说明字段格式，必须在真实模型负载下测量并替换，不能作为本机实测值。GPU 模式启动前查询 NVIDIA GPU 0 可用显存，要求 `expectedGpuMemoryMiB + 1024 MiB` 都可用；模型就绪后再次确认仍至少空余 1 GiB，否则停止模型并返回 `LOW_VRAM`。显存查询失败也会拒绝启动。CPU 模式须同时使用 `gpuLayers: 0` 和 `expectedGpuMemoryMiB: 0`。

只有第一条推理请求到来时才会启动服务；启动参数由代码生成并固定监听 `127.0.0.1`，不接受清单中的命令参数，也不启用工具/脚本接口。进程环境会清除 `LLAMA_ARG_*`、代理和其他用户覆盖值。健康检查通过后才发送推理请求；最后一个调用租约释放4分钟后停止进程。应用关闭时等待推理租约释放，再结束进程；子进程加入 `KILL_ON_JOB_CLOSE` Job Object，Host 异常退出时由 Windows 回收进程树。没有清单时仍兼容用户手动启动的回环服务；清单存在但格式/固定项不正确时会禁用模型请求，不自动回退到手动端点。哈希只证明本机文件匹配清单，清单本身不能替代上游来源/许可审查。

当前只验证了源代码构建和假运行时租约检查；b11259 可执行文件、CUDA DLL、GGUF 均未安装。健康端点、启动参数与实际版本的兼容性、进程停止及显存释放仍须在获批下载后验收。

Qwen3.5 GGUF 社区仓库近期出现转换及 hybrid architecture 相关问题记录。验收至少覆盖简体中文、严格 JSON、函数参数、工具调用、长短任务、取消、显存释放。若小K提供图片理解，还需校验 mmproj 与视觉请求；mmproj 未锁定前不承诺视觉场景。

## 4. ASR、TTS 与唤醒运行环境

- Qwen3-ASR 官方 qwen-asr 包支持 Python 3.12；其声明依赖 Transformers、Accelerate、Qwen Omni Utils、音频处理包等。需从固定上游 revision 生成哈希锁，不用 pip upgrade，也不把示例 Gradio/Flask Web UI 暴露网络。
- Qwen3-TTS 官方仓库建议新建隔离 Python 3.12 环境并通过 qwen-tts 加载模型。Windows wheel、GPU、音频依赖在此机器尚未验收，因此 ASR 和 TTS 先采用独立 venv；测出依赖兼容且可复现后再决定是否合并。
- Qwen3-ASR、TTS 都通过 ModelBroker 申请资源。语音采集可继续由独立轻量 CPU KWS/VAD 管理；LLM 正在 GPU 推理时，ASR/TTS 默认排队或走已验收 CPU 模式，不并驻大型 GPU 权重。
- sherpa-onnx 官方列有 Windows x64 支持与 CPU KWS。唤醒词模型、运行库和许可分别锁定。麦克风关闭由 Host 控制；worker 崩溃或重启不得自行恢复采集。

| 主 LLM | llama.cpp b11259 预发布版 / `d280808f5d82fcc3142b53f94ea5f594250cd765`，CUDA 13.4 候选 | 两个 Windows x64 发行资产及官方构建证明 SHA256 已登记；本机散列仍待核对 |
| ASR | CPython 3.12 x64 + qwen-asr 固定依赖 | D 盘独立 venv；生成带哈希的 requirements-asr.lock.txt |
| TTS | CPython 3.12 x64 + qwen-tts 固定依赖 | 初期独立 venv，不改变系统 Python |
| KWS/VAD | sherpa-onnx Windows x64 CPU 运行库 | 独立运行时，不安装 CUDA |
| MSIX | Windows SDK / Windows App SDK 包工程依赖 | 固定工程版本；用户证书私钥仅在本机，不提交 Git |

所有可执行程序走绝对路径。不给系统 PATH 添加模型/编译工具目录。Host 为 worker 构造最小环境变量。推理 worker 只能读取指定模型目录；Code Agent 不得读取权重、凭证或用户个人目录。安装过程中不执行远程 shell 安装脚本。

## 6. D 盘目标目录和空间预算

开发阶段模型权重放在仓库内已忽略的 `models/`；主模型默认位于 `models/llm/qwen3.5-4b/<revision>/`，ASR/TTS 位于各自的 `models/speech/<kind>/<model>/<revision>/`。正式安装时将权重迁移到 D 盘。用户数据、缓存、隔离工作区及评测样本在开发阶段也保持仓库外。正式部署目录建议如下；完整结构见 [整体架构与项目结构](../架构与接口/整体架构与项目结构.md)：

~~~text
D:\XiaoK\
├─ Runtime\
│  ├─ llama.cpp\b11259-d280808\cuda13.4\
│  ├─ python\asr312\
│  ├─ python\tts312\
│  └─ sherpa-onnx\<固定版本>\
├─ Models\
│  ├─ llm\qwen3.5-4b\<40位revision>\
│  ├─ speech\asr\qwen3-asr-0.6b\<40位revision>\
│  ├─ speech\tts\qwen3-tts-0.6b\<40位revision>\
│  └─ wakeword\zh-cn\<40位revision>\
├─ Data\
│  ├─ XiaoK.db
│  ├─ Backups\
│  └─ Logs\
├─ Workspaces\
└─ Evaluation\                 # 用户主动开启；可单独删除
~~~

应用 MSIX 包自身由 Windows 管理，不试图把包文件复制到 WindowsApps。正式部署时大型缓存、模型、数据库和评测样本放 D 盘仓库外；D 盘不存在或空间不足时明确停止，不静默写入系统盘。开发仓库内的 `models/` 仅是用户指定的临时存放位置，绝不能提交到 Git。

已知模型文件约 2.71 GB（Q4_K_M，2,707,513,696 字节）、1.88 GB（ASR 权重）、1.83 GB（TTS 权重），未含 mmproj、配置/tokenizer、Python wheel、推理 DLL、临时下载副本、安装包和备份。部署规划至少 30 GB 空闲空间；安装器根据锁文件的准确字节数重新计算总量。

## 8. 分项安装和联网确认

逐次确认是仓库已有授权规则，不因一次确认而允许批量下载：

1. 只读检查 D 盘空间、系统架构、驱动版本、已安装固定 SDK、现有 GPU/RAM 基线。
2. 生成完整安装清单供审阅：来源、版本/revision、许可、文件名/大小、SHA256、目标目录、回滚措施。
3. 单独确认并取得固定 llama.cpp Windows 发行资产，不用自动更新的 latest 指针。
4. 单独确认主 LLM 量化候选；下载、SHA256、GGUF 元数据和启停/显存测试全部成功后，才标为本机已验收。
5. 单独确认 Qwen3-ASR 权重与隔离 Python 环境，再分别测试 CPU/GPU 延迟和释放行为。
6. 单独确认 Qwen3-TTS 权重与其隔离环境，验证质量、首音延迟、取消和卸载。
7. 单独确认 sherpa-onnx 运行库和指定中文关键词模型；验证许可、误报/漏报和常驻功耗。
8. MiMo 单独决定是否下载；不是主模型、唤醒或首个集成切片的前置要求。
9. 产生本机 installation-manifest.json，记录版本、修订、校验值、许可、安装时间及配置 schema；不记录用户内容。
10. 推理服务仅 loopback、随机端口和短时令牌。验证局域网不可访问、Host 退出后端口/子进程均已关闭。

联网准备仅访问用户明确批准的官方或模型来源；日常推理不连接模型仓库或云服务。任何模型错误只呈现本地故障，不静默切云端。

## 9. 更新、恢复和回滚

- MSIX 负责桌面应用升级。升级前备份安全的配置和可迁移数据库，不包含原始通知正文。
- 模型和运行时采用并行版本目录；新版本验收后原子切换 active revision，保留最近一套已验收版本。
- 新版本启动/模型健康检查失败时关停子进程并切回上一版本；同时呈现失败摘要。
- 数据库迁移用可恢复事务。无法逆迁移时从备份恢复并告知用户，不覆盖工作区文件。
- 删除应用时先停止任务和释放音频/GPU，再让用户选择是否保留 D:\XiaoK\Data、模型、工作区与已同意保存的评测样本。
- 诊断包默认只含版本、启动错误类型和资源快照；显示内容预览，不含通知、录音、截图、token 或个人文件名。
