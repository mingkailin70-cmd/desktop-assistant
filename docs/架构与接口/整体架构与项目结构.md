# 小K整体架构与项目结构

> 文档状态：架构基线（设计完成；按表格区分已实现和待验收）。
> 版本基准：2026-10-03。硬件来自仓库维护说明；性能数据必须在目标电脑实测。
> 本文是部署规格与当前状态摘要。用户已授权本项目所需依赖、运行时及候选模型直接下载并执行必要联网命令；实际部署状态以锁清单和进度文档为准，仍需核验许可、来源及 SHA-256。

## 1. 产品边界

首版要通过六类场景各自的正常、失败、取消路径：打开应用、找文件、隔离工作区编程、理解聊天、起草回复、确认后发送。

- 主机侧推理、语音识别和语音合成本地运行，不允许云端推理回退。
- 小K在当前 Windows 登录会话运行。桌宠、托盘、快捷键与可见任务状态属于 Host；大型模型按需启动。
- ToolBroker 是唯一副作用入口。模型只提交有目标、参数、前置条件和可观察预期的动作提案。
- 发送、删除、支付、管理员操作须展示最终目标和内容并由用户确认。发送状态不确定时转人工核对，不自动重试。
- 微信和 QQ 通知按经过验证的发布者身份过滤。其他来源的正文不得读取、记录或送入模型；不得读客户端数据库或注入进程。
- 用户可见地暂停通知监控、停麦、取消任务。停麦不依赖模型进程状态。
- 用户输入、通知正文、OCR、网页和模型输出均为不可信数据。

### 2.1 进程与故障隔离

| 进程/模块 | 职责与常驻方式 | 失败处理 |
| --- | --- | --- |
| XiaoK.Host | WPF 单实例、桌宠、托盘、输入/输出设备控制、会话状态；当前登录会话常驻 | 不随模型退出；始终可停麦、取消和退出 |
| XiaoK.Inference worker | 单个 LLM 后端；任务时启动，空闲约 3–5 分钟卸载 | 超时取消并回收子进程与显存；故障不切云端 |
| XiaoK.Voice worker | 轻量 CPU KWS/VAD 常驻；ASR/TTS 按需 | Host 独立关闭音频采集；重启不得自动恢复录音 |
| Windows Adapter | 通知监听和应用身份过滤 | 权限撤销、锁屏或来源不明即停止分析 |
| Code Agent worker | 用户选定目录下的隔离工作区读写、差异和获批命令 | 可取消；结束后提供可审查补丁，不自动推送 |

本地推理 API 仅绑定 127.0.0.1 的本地端口，由 Host 管理启动令牌和生命周期，关闭时撤销令牌并结束服务。不得监听局域网地址或自动开放防火墙。推理模型无权绕过 ToolBroker。

## 3. 任务协议与关键数据流

### 3.1 通用任务

1. Host 创建唯一 Task，状态为 Queued；来源为文本、快捷键或唤醒后的语音。
2. 编排器做本地意图识别并检查必要信息，不足时向用户澄清。
3. ModelBroker 按交互优先级、GPU 预算和取消令牌调度。
4. 模型仅生成版本化动作提案：工具名、目标、参数、前置条件、可观察预期与风险级别。未知工具或字段直接拒绝。
5. ToolBroker 独立校验权限、目标身份、路径、范围和前置条件；需确认的动作先展示 Preview。
6. 工具执行后由 ToolBroker 核验真实结果，明确区分失败、部分成功、超时和不确定。
7. Host 展示结果；只持久化最小任务状态，不保存默认禁存的通知正文、录音或截图。

### 3.2 消息通知

通知回调采用惰性正文读取：先读取最少的发布者身份；确认是微信/QQ、该应用监控已开启、会话符合私聊策略、系统未锁屏且事件未重复后，才取通知正文。未知来源的正文不得物化。去重与限流按应用隔离。

没有正文时只提示“有新消息，请手动打开会话”，不自动切换窗口。显示名不能作为发送目标的权威身份；当前 QQ `K`、微信 `L` 白名单只允许预览，实际发送前仍须绑定独立核验的稳定客户端身份。理解、草拟、发送预览是分离的任务阶段。发送预览逐项显示收件人、正文和附件；发送结果不确定时暂停并请求人工核对。

### 3.3 编程任务

CodeTask 只有在用户选择仓库并授权目录后才能开始。代理仅能在该授权根内进行受限读写、搜索和获批命令；默认不能读取凭证、访问目录外文件、运行任意脚本、联网或推送 Git。每个工具步骤边界向交互任务让位。最终展示差异与命令结果供用户确认；越界写入直接拒绝。

## 4. 模型与资源调度

目标硬件：Core Ultra 9 275HX、32 GB RAM、RTX 5060 Laptop 8 GB、Intel 集显。GPU 显存值是动态快照，启动模型前必须重新采样，并保留至少约 1 GiB 独显余量。

| 优先级 | 工作 | 资源策略 |
| --- | --- | --- |
| P0 | 停麦、取消、任务状态 | 不等待模型锁，立即响应 |
| P1 | 用户当前交互 | 可在编程代理工具步骤边界抢占；大型 GPU 模型同时最多一个 |
| P2 | KWS/VAD | 小型 CPU 模型常驻 |
| P3 | ASR/TTS、通知分析 | 进入同一资源队列；先测 CPU，再按需申请 GPU；不使用云端兜底 |
| P4 | 编程代理 | 背景优先级；工具步骤后让位，必要时保存状态等待 |

ModelBroker 状态：Stopped → Starting → Ready → Busy → Draining → Stopped，并允许 Faulted。托管 GPU 模型启动前须通过 NVIDIA 显存预算检查，健康后复查至少 1 GiB 余量；失败时终止 worker 并返回 `LOW_VRAM`。若子进程未释放资源，Host 终止 worker 并呈现故障状态。该预算策略尚未由实际模型负载校准。

LLM 空闲 3–5 分钟卸载。小K空闲时的新增独显显存目标低于 300 MiB。持续记录 GPU 专用/共享显存、RAM、CPU、模型启动时间、首 token、生成速度、ASR 实时率与 TTS 首音延迟。nvidia-smi 中 C+G 列表不代表每个进程都独占相同显存。

## 5. 存储和隐私

~~~mermaid
erDiagram
  Task ||--o{ TaskEvent : has
  Task ||--o| CodeTask : may_be
  CodeTask ||--o{ Artifact : produces
  Task { string task_id PK string type string state datetime created_at datetime updated_at }
  TaskEvent { string event_id PK string task_id FK string state datetime at string safe_detail }
  CodeTask { string task_id PK string workspace_id string checkpoint string review_state }
  Artifact { string artifact_id PK string task_id FK string relative_path string sha256 }
~~~

通知正文只存在于内存短时对象，不写数据库、日志、崩溃报告或遥测。待处理正文使用 TTL，重启清空。只保存最小任务 ID、状态、脱敏错误类别和编程任务检查点。消息适配器不保存联系人或聊天历史。

评测样本默认关闭；用户同意后才保存脱敏样本。评测数据独立目录、可单样本删除。日志用字段白名单和容量上限。备份排除未授权原始内容、密钥和凭证。
