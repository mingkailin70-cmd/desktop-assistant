# 本机单文件回收站操作边界

## 可用命令

用户可输入“移入回收站：本机完整文件路径”，例如：

```text
移入回收站：D:\Users\你\Documents\草稿.txt
```

命令只接受设置中已配置搜索根内的单个本机普通文件。目录、网络路径、备用数据流、通配符、重解析点、硬链接及路径过长的文件会被拒绝。暂不支持批量、文件夹、永久删除或任意 Shell 命令。

## 确认与隐私

工具先打开并检查文件、父目录和搜索根，取得文件身份、大小与修改时间快照，然后在任务中心显示规范化后的完整目标路径。用户确认前不会调用 Windows 删除接口。批准后重新核对路径仍指向同一文件、文件元数据未变化，且目录身份与批准时一致；任何变化都停止。

审批待办只短时保存在内存。SQLite 审计仅记录固定动作 ID 和确认/拒绝结果，不记录文件路径、请求原文或内容。任务历史只保存固定任务类别和不含目标路径的结果。后台任务不发送键鼠输入、不切换窗口，也不弹出模态窗口。

## Windows 回收站调用

批准后调用 Windows Shell 的单文件删除操作，并设置“保留撤销信息/回收站”及静默、不递归、不连带处理关联文件等标志。源路径必须是完整本机路径；为匹配 Shell 接口限制，本工具拒绝 260 个字符及以上的路径。调用后检查 Shell 返回值、取消标志、源路径是否消失及原父目录是否仍可核验。

如果调用失败且原文件身份仍在原位，任务报告失败；如果文件已经离开原位置但 Shell 结果或目录状态无法确认，任务进入“结果待核对”，提示用户检查原目录和回收站，不会自动重试。回收站状态因 Windows Shell 接口而异，成功状态以 Shell 返回成功且原路径已不存在为准。

## 边界与验收状态

Shell 回收站接口接收文件路径，而不是已验证的文件句柄。因此实现会在任务中心等待确认后再次核验，并在后台线程中紧邻调用 Shell；但 Windows 没有为该 Shell 操作提供按文件 ID 原子投递回收站的接口，极短的最终路径检查与调用之间仍有并发替换窗口。若不能接受此系统边界，不应对可能由其他程序同时替换的目标文件使用该操作。独立安全检查只使用合成临时文件并覆盖拒绝、无审批、越界和固定参数路径；不向用户实际回收站投放测试项目。签名安装版和真实用户目录操作仍待后续安装验收。
