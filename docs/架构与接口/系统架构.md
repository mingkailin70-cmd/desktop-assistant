## 进程与边界

小K运行在当前登录用户会话，入口包括桌宠、托盘、Ctrl+Shift+K、文字和经用户授权后的语音。Host负责UI、状态、取消和审批。语音、推理和后台代码代理可作为独立恢复的工作进程。组件之间优先使用限制当前用户SID的Named Pipe；本机HTTP只绑定127.0.0.1。

TaskOrchestrator管理持久状态、步骤、超时、取消和恢复点。ModelBroker统一大型推理资源租约，一次只允许一个大型GPU模型；交互请求在代码代理工具步骤边界可抢占调度。ToolBroker为唯一副作用入口；模型只能返回结构化动作建议。工具执行后重新读取系统状态核验。

当前 `ModelBroker` 代码提供有界的交互优先等待队列（最多128项），并为后台推理提供单步骤租约接口；隔离编程代理的文件选择与补丁生成分别在后台步骤中取得租约，步骤间允许交互请求先运行。该调度器不读取GPU显存、不启动或卸载模型进程，也不证明模型可在当前机器安全运行。

## 消息通知流

MSIX安装并取得用户明确授权后，由Windows UserNotificationListener前台事件接收通知变化。当前实现先检查包身份和权限，再按系统发布者AppUserModelID allowlist 过滤；过滤前不得读取/保存/传送其他应用正文。监听默认关闭，需在设置中分别启用微信/QQ并配置已核实的发布者 AUMID；现存通知只建立启动基线，不会被当作新消息处理。

适配器判断来源、私聊属性、去重和速率。纯策略层按应用区分哈希去重标识，默认两分钟去重，并以会话标识哈希在内存实施每分钟最多十条的模型分析限速；缓存设有容量上限，超过上限时退回人工查看。当前 Host 已接入原生前台监听、来源白名单、权限状态检查、锁屏时安全拒绝和设置入口，但尚未制作带有效身份的 MSIX，也未在本机授权运行。微信/QQ通知的私聊分类尚未由真实样本证明，因此监听实现当前传入未知会话类型；策略会在正文读取器执行前停止，不读取正文、不送模型，只显示请手动查看提示。后续须完成每款至少30条测试，才能决定是否开放正文分析；限速值也未通过真实负载校准。

## 编程代理

当前已接入一个不执行命令的本地补丁生成切片：项目路径必须由用户在设置中选择；小K从所选目录创建基线和隔离副本，模型仅从受限文本文件清单选择最多4个文件并生成这些文件的修改。模型输出经路径白名单和大小校验后只写入仓库外的任务工作区，Host 展示差异并把任务标为等待审阅。它不会将补丁复制回原项目，也不运行 shell、脚本、构建或测试命令。快照排除 `.git`、常见凭证路径和链接/重解析点，并在复制、读取基线及写入工作副本时做 Windows 句柄最终路径检查；未知格式的源码密钥仍有被模型看到的风险。最近任务读取器只接受固定任务目录名、状态和时间字段，并核实任务目录、状态文件和工作区边界；不接受状态文件里的额外内容，也不续跑任务。现有无第三方依赖安全检查共16项通过，含硬链接状态文件和目录联接检查；真实模型行为与文件符号链接仍待补验。

后续完整CodeAgent目标（尚未实现）是增加作用域化检索、固定命令审批清单、命令结果和用户确认后的合并；依赖下载与新联网命令仍需逐项批准。任意shell、工作区外写入、删除和 Git push 不开放。首版隔离补丁切片不执行命令，也不提供自动合并入口。长任务需支持 queued、planning、awaiting_approval、running、paused、completed、failed、cancelled 和 outcome_uncertain 状态。

## 工具与审批

执行顺序：schema验证 → 目标/范围解析 → 权限评估 → 用户预览/确认（需要时）→ 重新定位目标 → 执行 → 独立核验 → 保存脱敏状态。外发、删除、支付、管理员操作必须确认最终目标、文字、附件或参数。外发结果不明则转人工核对，不重试。浏览器优先DOM/ARIA；Windows应用优先系统API/UIA；视觉仅在结构信息不足时使用。

## 数据

默认个人数据、SQLite库、模型、缓存和可删除评测样本均在D盘仓库外。通知正文、原始录音、完整截图和模型回答默认不进入持久日志。用户同意留作评测的样本要脱敏、单独管理并可删除。SQLite迁移需备份，恢复时不能自动重放带外部副作用的步骤。
