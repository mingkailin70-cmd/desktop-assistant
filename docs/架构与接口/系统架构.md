# 小K系统架构与数据流

更新：2026-09-29。当前有WPF Host和工具切片；下列架构描述目标系统，不能视为已交付功能。产品范围和发布门槛以[实施计划与模型选型](../产品与进度/实施计划与模型选型.md)为准。

## 进程与边界

小K运行在当前登录用户会话，入口包括桌宠、托盘、Ctrl+Shift+K、文字和经用户授权后的语音。Host负责UI、状态、取消和审批。语音、推理和后台代码代理可作为独立恢复的工作进程。组件之间优先使用限制当前用户SID的Named Pipe；本机HTTP只绑定127.0.0.1。

TaskOrchestrator管理持久状态、步骤、超时、取消和恢复点。ModelBroker统一大型推理资源租约，一次只允许一个大型GPU模型；交互请求在代码代理工具步骤边界可抢占调度。ToolBroker为唯一副作用入口；模型只能返回结构化动作建议。工具执行后重新读取系统状态核验。

## 消息通知流

MSIX安装后由Windows UserNotificationListener在用户明确同意后接收通知变化。通知事件首先按系统发布者AppUserModelID过滤为微信或QQ，再进入独立应用适配器；过滤前不得读取/保存/传送其他应用正文。

适配器判断来源、私聊属性、去重和速率。私聊无法确定时只显示普通提示，不送模型。正文可见、权限有效、会话解锁时发送单条通知文本给本机推理，作为一次性的MessageNotice处理；没有正文时提示用户手动打开应用，不抢窗口。正文与模型回答不写日志。当前仓库只提供策略骨架，尚无原生通知监听器或MSIX安装。

## 编程代理

本地CodeAgent先创建项目专属隔离工作区，再经作用域化读/搜索能力观察文件，生成统一diff。只允许受批准的本地命令和超时；依赖下载、新的联网命令和外发动作逐项请求批准。凭证读取、工作区外写入、任意shell、删除、git push均拒绝。UI显示文件差异及命令结果；只有用户批准才将补丁合回项目。长任务有queued、planning、awaiting_approval、running、paused、completed、failed、cancelled和outcome_uncertain状态。

## 工具与审批

执行顺序：schema验证 → 目标/范围解析 → 权限评估 → 用户预览/确认（需要时）→ 重新定位目标 → 执行 → 独立核验 → 保存脱敏状态。外发、删除、支付、管理员操作必须确认最终目标、文字、附件或参数。外发结果不明则转人工核对，不重试。浏览器优先DOM/ARIA；Windows应用优先系统API/UIA；视觉仅在结构信息不足时使用。

## 数据

默认个人数据、SQLite库、模型、缓存和可删除评测样本均在D盘仓库外。通知正文、原始录音、完整截图和模型回答默认不进入持久日志。用户同意留作评测的样本要脱敏、单独管理并可删除。SQLite迁移需备份，恢复时不能自动重放带外部副作用的步骤。
