# 小K系统架构与数据流

完整的目标逻辑架构、进程故障隔离、模型调度、存储策略及目录树见[整体架构与项目结构](整体架构与项目结构.md)。本文保留现有数据流与接口边界的细节；设计描述不代表功能已交付。

更新：2026-09-30。当前有 WPF Host、有限工具切片、不执行命令的隔离代码补丁生成链路、SQLite脱敏任务状态、联系人固定回复风格偏好和固定字段审批审计，以及一个尚待本机安装验收的前台 Windows 通知监听实现；迁移仅有合成数据证据，未读取用户数据。下列其余架构描述仍是目标系统，不能视为已交付功能。产品范围和发布门槛以[实施计划与模型选型](../产品与进度/实施计划与模型选型.md)为准。

## 进程与边界

小K运行在当前登录用户会话，入口包括桌宠、托盘、Ctrl+Shift+K、文字和经用户授权后的语音。Host负责UI、状态、取消和审批。语音、推理和后台代码代理可作为独立恢复的工作进程。组件之间优先使用限制当前用户SID的Named Pipe；本机HTTP只绑定127.0.0.1。

TaskOrchestrator管理持久状态、步骤、超时、取消和恢复点。ModelBroker统一大型推理资源租约，一次只允许一个大型GPU模型；交互请求在代码代理工具步骤边界可抢占调度。ToolBroker为唯一副作用入口；模型只能返回结构化动作建议。工具执行后重新读取系统状态核验。

当前 `ModelBroker` 代码提供有界的交互优先等待队列（最多128项），并为后台推理提供单步骤租约接口；隔离编程代理的文件选择与补丁生成分别在后台步骤中取得租约，步骤间允许交互请求先运行。可选的 `LlamaCppModelRuntime` 在托管清单有效时按需启动固定版本进程、检查文件 SHA-256、独占单模型步骤，并在空闲4分钟后卸载；退出时会等到租约清零再停止进程。子进程加入 `KILL_ON_JOB_CLOSE` Job Object，Host 意外退出时由 Windows 回收该进程树。GPU 模式用 `nvidia-smi` 要求启动前满足实测显存预算与 1 GiB 余量，并在模型就绪后复查余量；准入策略尚未用实际运行包或权重验收，预算须 P0 校准。没有清单时仅使用用户配置的回环服务，显存准入不覆盖该手动模式。

## 消息通知流

MSIX安装并取得用户明确授权后，由Windows UserNotificationListener前台事件接收通知变化。当前实现先检查包身份和权限，再按系统发布者AppUserModelID allowlist 过滤；过滤前不得读取/保存/传送其他应用正文。监听默认关闭，需在设置中分别启用微信/QQ并配置已核实的发布者 AUMID；现存通知只建立启动基线，不会被当作新消息处理。

适配器判断来源、私聊属性、去重和速率。纯策略层按应用区分哈希去重标识，默认两分钟去重，并以会话标识哈希在内存实施每分钟最多十条的模型分析限速；缓存设有容量上限，超过上限时退回人工查看。当前 Host 已接入原生前台监听、来源白名单、权限状态检查、锁屏时安全拒绝和设置入口，但尚未制作带有效身份的 MSIX，也未在本机授权运行。微信/QQ通知的私聊分类尚未由真实样本证明，因此监听实现当前传入未知会话类型；策略会在正文读取器执行前停止，不读取正文、不送模型，只显示请手动查看提示。后续须完成每款至少30条测试，才能决定是否开放正文分析；限速值也未通过真实负载校准。

## 编程代理

当前已接入一个由用户选择项目的隔离补丁流程：Host 创建基线和工作副本，模型最多选择4个受限文本文件，补丁只写入任务工作区并经过路径/大小检查。审阅窗展示完整差异；用户可不运行命令直接保留补丁，也可单独批准一个固定 .NET 依赖还原/测试配方。两条命令均在 Windows AppContainer 运行，只向任务工作区授予写权限、向固定 .NET 运行时授予只读权限；子进程放入 Host 的 Job Object；运行前将 ACL 范围与临时身份写入当前用户专属的恢复清单，正常结束时清理，Host 被强制终止后由下次启动先恢复；恢复失败或清单损坏时拒绝运行隔离命令。restore 获得 `internetClient` 能力且 NuGet 源仅 nuget.org；项目目标仍能使用该能力，test 不配置网络能力。模型不能提交命令、任意 shell、删除、Git 或合并操作。离线探针验证任务工作区可写、兄弟目录哨兵不可读写、命令超时/取消后子进程停止，并在模拟 Host 强杀后验证下次启动清理遗留 ACL/身份；真实项目构建/测试、联网行为、断电和文件系统故障仍未验收，不宣称所有越界副作用为零。快照排除 `.git`、常见凭证路径和链接/重解析点，并在复制、读取基线及写入工作副本时做 Windows 句柄最终路径检查；未知格式的源码密钥仍有被模型看到的风险。最近任务读取器只接受固定任务目录名、状态和时间字段，并核实任务目录、状态文件和工作区边界；不接受状态文件里的额外内容，也不续跑任务。Host 按本次进程启动时间将旧的 `queued`/`planning`/`running`/`verifying` 任务显示为结果待核对；隔离编程任务状态文件只读，不自动续跑、重试或重放。应用名仅通过固定别名映射到允许列表；未知应用拒绝启动。应用启动请求发出前可以取消；请求发出后取消或窗口核验超时则记录结果待核对，不自动重试。文件搜索现通过稳定目录句柄枚举目录项，并对打开后的对象核对卷序列号、128位文件 ID 和最终路径。当前43项安全检查通过，覆盖 AppContainer 文件、超时、取消和 Host 强杀恢复探针以及代码审批边界、SQLite清理/脱敏/迁移/备份/恢复与既有工具、通知、模型准入边界；真实模型行为、实际 GPU 预算、对抗性并发目录替换和文件符号链接仍待补验。

后续完整CodeAgent目标是增加作用域化检索、更多命令审批配方、结果核验和用户确认后的安全合并。当前只提供一个固定 .NET 依赖还原/测试配方，用户必须审阅差异并单独批准；模型不能提交命令。AppContainer 离线探针已验证工作区文件边界；restore 启用的 `internetClient`、真实项目运行和所有工作区外副作用仍未证明。任意shell、删除和 Git push 不开放，补丁仍不自动合入原项目。长任务需支持 queued、planning、awaiting_approval、running、paused、completed、failed、cancelled 和 outcome_uncertain 状态。

## 工具与审批

执行顺序：schema验证 → 目标/范围解析 → 权限评估 → 用户预览/确认（需要时）→ 重新定位目标 → 执行 → 独立核验 → 保存脱敏状态。外发、删除、支付、管理员操作必须确认最终目标、文字、附件或参数。外发结果不明则转人工核对，不重试。SQLite v3审批审计只保存固定动作 ID、固定决定、记录 ID 与时间；不持久化预览内容，也不构成授权恢复或动作重放机制。固定 .NET 测试得到明确用户批准后先写审计记录，写入失败则不启动命令。浏览器优先DOM/ARIA；Windows应用优先系统API/UIA；视觉仅在结构信息不足时使用。

## 数据

默认个人数据、SQLite库、模型、缓存和可删除评测样本均在D盘仓库外。通知正文、原始录音、完整截图和模型回答默认不进入持久日志。用户同意留作评测的样本要脱敏、单独管理并可删除。设置页的本地清理会清空SQLite任务、偏好和审批记录，保留迁移标记；移除设置JSON中的旧联系人偏好副本，并删除数据目录内可识别的小K旧任务/备份/暂存文件。用户另存到外部或自定义名称的备份、隔离工作区和评测样本不在清理范围。SQLite迁移需备份，恢复时不能自动重放带外部副作用的步骤；当前清理与恢复仅有合成数据验证，真实用户数据演练仍待完成。
