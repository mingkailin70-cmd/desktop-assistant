## 1. 适用范围与所有权

| 组件 | 提供的接口 | 权限 |
| --- | --- | --- |
| `XiaoK.Host` | 用户输入、状态呈现、权限预览与决定、取消、Windows 本地固定短语唤醒与锁屏停麦 | 不能绕过 ToolBroker 直接执行模型提案 |
| `TaskOrchestrator` | 任务生命周期、步骤、取消传播、事件序列 | 唯一可持久化任务状态的组件 |
| `XiaoK.Voice` | ASR/TTS、音频推理协议与设备状态；低功耗 KWS/VAD 尚待接入 | 不执行电脑操作；麦克风音频默认不持久化 |
| `ModelBroker / XiaoK.Inference` | 模型租约、结构化生成、资源报告 | 只能返回内容/提案，不能调用工具或改变权限 |
| `DecisionProvider` | 规则或候选模型的固定选项选择 | 只能在预定义可执行选项中选择，不发放确认 |
| `ToolBroker` | 工具发现、参数校验、权限、执行、独立核验 | 唯一副作用入口；拒绝未知工具/未确认动作 |
| 适配器 | Windows、文件、Browser静态/隔离动态网页与短时匿名网页会话、公网文件下载、Edge窗口定位、微信通知、QQ通知、隔离CodeAgent | 只接受 ToolBroker 发出的作用域请求

应用启动使用 `app.launch.v1`；切换到已打开的窗口使用 `window.activate.v1`。两种动作都只接受本机固定配置映射出的 `app_id`，VS Code 另绑定 `workspace_id=xiaok`。窗口切换拒绝原始 HWND、进程 ID、窗口标题、坐标或命令参数；找不到已打开的目标时不会改为启动应用。任何模型输出的任意 exe 路径、shell 命令或坐标均不是有效参数。

当前应用启动适配器在调用 Windows 之前先检查取消信号；调用系统启动请求后若收到取消，或在时限内未能独立核验目标窗口，结果标为 `outcome_uncertain`，提示用户手动核对且不自动重试。取消只能阻止尚未发出的启动请求，不能撤销已交给 Windows 的请求。

Host 只将明确的中文/英文应用别名映射为本地固定 ID（VS Code 小K项目、Edge、资源管理器、微信、QQ）；无法识别的名称以 `APP_NOT_SUPPORTED` 结束，不猜测默认应用。最终路径仍必须匹配本机配置的应用白名单。

应用路径由用户在设置页配置；验证时要求路径是存在的本机程序文件，且文件名分别匹配 `Code.exe`、`msedge.exe`、`Weixin.exe` 或 `QQ.exe`。网络共享与映射网络盘不接受。VS Code 程序路径和项目目录必须同时提供或同时留空；项目目录需包含 `XiaoK.sln`。Edge、微信和 QQ 可留空以关闭相应启动入口。配置保存后重启 Host 生效。此配置不扩大模型可调用的固定应用 ID 集合。

`window.activate.v1` 再按可执行映像路径匹配白名单进程，并要求 VS Code 窗口标题包含配置的小K项目目录名；带 `[SSH:…]`、`[WSL:…]`、`[Dev Container:…]` 或 `[Codespaces:…]` 标记的远程窗口不作为本地项目窗口。目标必须唯一：零个匹配时返回 `WINDOW_NOT_FOUND`，多个不同句柄匹配时返回 `WINDOW_TARGET_AMBIGUOUS` 并要求用户手动选择，不会任取一个窗口。唯一匹配时，适配器只恢复该窗口并请求 Windows 前台切换；完成后独立读取前台 HWND，只有目标句柄仍有效、可见且与前台句柄一致时才返回成功。Windows 前台限制导致切换失败时提示用户手动切换，不注入按键、不发送鼠标输入，也不重试启动应用。VS Code `app.launch.v1` 使用 `--new-window` 和固定项目路径，并用同一标题规则确认本地项目窗口；既有 SSH 窗口不满足本地窗口验证。

## 2. 传输与通用封套

本地进程通信优先采用限当前用户 SID 的 Windows Named Pipe；控制通道为四字节小端长度前缀加 UTF-8 JSON，单条控制消息上限暂定 1 MiB。音频、截图等大载荷经专用流或受限临时文件能力引用传输。管道端点只由 Host 创建并发布给其启动的工作进程；子进程连接时校验当前登录会话和一次性启动令牌。本地 HTTP 备选必须仅绑定 `127.0.0.1` 并使用会话令牌。

所有时间使用 UTC ISO 8601，ID 是不含个人信息的随机 UUID，`deadline_utc` 由接收方强制执行。每次请求有唯一 `request_id`；重试读取/查询可复用相同语义，但产生副作用的 `action_id` 不能自动重放。任务内事件 `seq` 严格单调递增。

请求封套：

```json
{
  "protocol_version": "1.0",
  "kind": "request",
  "request_id": "9de10914-9273-41a4-9185-b05466b33496",
  "operation": "task.create",
  "task_id": null,
  "deadline_utc": "2026-09-29T07:00:30Z",
  "payload": {
    "source": "text",
    "input": "打开 VS Code 中的小K项目"
  }
}
```

成功响应使用相同 `request_id`，`result` 仅包含操作结果；失败响应只给 `error`，不提供误导性的部分成功数据：

```json
{
  "protocol_version": "1.0",
  "kind": "response",
  "request_id": "9de10914-9273-41a4-9185-b05466b33496",
  "ok": true,
  "result": {
    "task_id": "96c36e7c-eec8-4d72-88a4-c42cc225f357",
    "status": "queued"
  }
}
```

失败例：

```json
{
  "protocol_version": "1.0",
  "kind": "response",
  "request_id": "9de10914-9273-41a4-9185-b05466b33496",
  "ok": false,
  "error": {
    "code": "USER_SESSION_LOCKED",
    "message": "当前会话已锁定，桌面操作暂停。",
    "retryable": true,
    "retry_after_ms": null
  }
}
```

`message` 是可展示的简短文本，不包含密钥或聊天正文；调用方按 `code` 决定行为，不解析 message 文案。未授权客户端、未知 `operation`、超长消息或不支持的主版本都在解析/调度前拒绝。

## 3. 任务与事件接口

| 操作 | 发起方 → 接收方 | 主要载荷 | 结果 |
| --- | --- | --- | --- |
| `task.create` | Host/Voice → Orchestrator | 来源、文本或 ASR 文本引用、选区能力引用 | `task_id`、`queued` |
| `task.get` | Host → Orchestrator | `task_id` | 持久状态、最近步骤、是否等待用户 |
| `task.cancel` | Host → Orchestrator | `task_id`、可选原因 | 已受理取消；最终状态由事件/查询确认 |
| `event.subscribe` | Host → Orchestrator | `task_id`、`after_seq` | 从该序号之后重放事件，再接实时事件 |
| `approval.decide` | Host → ToolBroker | `approval_id`、`action_digest`、`approved` | 受理/拒绝；不直接表示操作已完成 |

持久状态枚举：`queued`、`planning`、`awaiting_approval`、`running`、`paused`、`completed`、`failed`、`cancelled`、`outcome_uncertain`。呈现态 `idle`、`listening`、`speaking` 不取代持久状态。`completed` 必须由任务完成条件或工具独立核验触发；模型自述不构成完成凭证。

取消请求示例：

```json
{
  "protocol_version": "1.0",
  "kind": "request",
  "request_id": "bd8bb84e-4c93-434a-845d-bc11936d76ba",
  "operation": "task.cancel",
  "task_id": "96c36e7c-eec8-4d72-88a4-c42cc225f357",
  "deadline_utc": "2026-09-29T07:01:00Z",
  "payload": {
    "reason": "user_pressed_stop"
  }
}
```

取消是协作式：Orchestrator 持久化取消意图，停止后续步骤，并将信号传播至 Voice、ModelBroker 和适配器；正在执行的不可中断系统调用可能先返回。对于消息发送、删除、支付等可能已产生外部效果的步骤，若取消时无法核验，结果应为 `outcome_uncertain`，禁止自动补发或重试。

当前 Host 队列以 `TaskExecutionAdmissionGate` 原子仲裁“取消排队任务”和“工作线程开始执行”。任务取消先赢时，Host 立即将显示状态切为 `cancelled`、从可取消清单移除并持久化该状态，队列读者随后跳过该项；本地状态写入失败时，当前进程仍显示已撤销，重启恢复会保守显示“结果待核对”。工作线程先赢时任务已进入运行态，取消仅向当前执行步骤发送取消信号，不声称能撤回已交给 Windows 的不可逆请求。接纳状态事件先发出，工作线程收到事件屏障后才竞争准入，避免 UI 出现过期的“已排队”状态。该实现不保存任务正文，也不重放任务。

R1新增`TaskFailureSafetyPolicy`：Host在进入已识别的副作用路由前设置执行标记；应用启动/窗口切换、文件复制/改名/移动/压缩、公网下载与隔离编程路由发生未处理异常、执行中取消或超时后，若无法从适配器得到可核验结果，则持久化`OutcomeUncertain`和固定错误类别，并指引用户先核对目标状态。只读搜索/网页读取不套用副作用分类；路由前失败仍为失败或取消。当前`message.send.v1`只显示预览，未接发送适配器，因此发送类别暂未启用此规则；接入实际发送器时必须纳入并验证“不确定不重发”。此回退只覆盖逃逸出适配器的未处理异常，适配器返回的具体失败/核验结果仍以各工具契约为准。

事件封套：

```json
{
  "protocol_version": "1.0",
  "kind": "event",
  "event_id": "2015fbc9-0ef2-4367-87ae-e6c9dfac02ba",
  "task_id": "96c36e7c-eec8-4d72-88a4-c42cc225f357",
  "seq": 3,
  "at_utc": "2026-09-29T07:00:09Z",
  "type": "task.state_changed",
  "payload": {
    "from": "planning",
    "to": "running",
    "step_id": "d8d6bf51-f11d-4a70-9c45-95bd4ae56e9e"
  }
}
```

首版事件类型至少有 `task.state_changed`、`approval.requested`、`approval.resolved`、`tool.started`、`tool.verified`、`tool.failed`、`model.started`、`model.stopped`、`resource.mode_changed`、`voice.device_changed`。订阅重连按 `after_seq` 恢复；事件供展示与诊断，`task.get` 的持久状态仍为最终依据。客户端应容忍未知的新增事件类型。

## 4. 结构化动作与工具接口

模型或规则只可产生 `ActionProposal.v1`。`tool_id` 必须在 ToolBroker 注册表中，`arguments` 必须符合对应 JSON Schema；`target_ref` 只能引用当前选区、搜索结果、已配置应用或当次发现的控件，不接受未经发现的任意目标。`preconditions` 和 `expected_outcome` 是工具可验证条件，不由模型自行宣布通过。当前 .NET 提案使用 `ToolPrecondition` 与 `ToolExpectedOutcome` 固定枚举：应用启动要求允许列表应用，窗口切换要求允许列表应用与已存在窗口，文件搜索、文本摘要和同目录重命名要求已配置根目录，新建文本与单文件复制还要求固定导出目录，单文件移动要求已配置源搜索根和目标搜索根，用户粘贴的消息分析/草稿要求本次提供单条消息；后台通知分析使用独立的 `VerifiedPrivateNotice` 前置条件；发送要求完整预览，编程任务要求显式配置的项目及隔离工作区。预期结果也必须与工具 ID 对应。ToolBroker 按工具 ID 精确比较枚举组合，再由对应适配器检查运行时事实；自由文本不能代替前置条件或预期结果。

R3 加入静态网页工具 `browser.read.public.v1`：唯一参数为 `url`，目标固定为 `public-web-page`，要求 `UserProvidedPublicWebPageUrl` 并绑定 `PublicWebPageSnapshotReturned`。ToolBroker 只接受用户明确提供的 HTTPS 公网主机地址，经 `ExecuteBackgroundAsync` 调用 `IPublicWebPageReader.ReadPageAsync`；不能从网页正文创建后续动作。读取网络与静态解析的限制见[公开网页静态读取边界](公开网页静态读取边界.md)。

R3 增加显式隔离动态只读工具 `browser.read.dynamic.public.v1`：唯一参数仍为用户明确提供的 `url`，目标固定为 `public-dynamic-web-page`，要求 `UserProvidedDynamicPublicWebPageUrl` 并绑定 `DynamicPublicWebPageSnapshotReturned`。只有以“读取动态网页：”开头的用户命令进入该路由；其余网页入口继续禁用脚本。ToolBroker 经 `ExecuteBackgroundAsync` 调用 `IDynamicPublicWebPageReader.ReadDynamicPageAsync`。适配器在独立无头Edge中的 `sandbox="allow-scripts"` iframe运行下载HTML内联脚本；CSP位于所有网页字节之前且限制外部/本机网络及提交能力，BrowserContext路由、Service Worker和下载也保持阻断。不给同源、用户Cookie、点击/填写/提交权限。网页仍是不可信数据；动态页需要被阻止的外部子资源时可以只返回部分内容。详细边界和离线夹具结果见[公开网页静态与隔离动态读取边界](公开网页静态读取边界.md)。

R3.1新增短时匿名浏览器工作流，固定工具为`browser.session.open.v1`、`browser.session.snapshot.v1`、`browser.session.click-button.v1`、`browser.session.fill-text.v1`和`browser.session.close.v1`；全经ToolBroker后台通道，参数绑定HTTPS公网网址、随机会话令牌、当前随机快照令牌、ARIA角色及精确可访问名称。只有固定中文用户命令进入这些工具，模型与网页文本不能发起或扩大动作。最多一个内存会话，45秒闲置或2分钟绝对寿命后关闭；Host退出、会话命令取消或每步5秒超时会清理。初次网页由逐跳HTTPS/DNS公网校验器下载，浏览器Context无用户Cookie且所有子请求被阻止；渲染位于无同源sandbox iframe，并禁用WebRTC、WebSocket、EventSource、Worker、BroadcastChannel、sendBeacon和弹窗API。只允许唯一的原生`type=button`动作和普通`input[type=text|search]`/`textarea`填写；提交/reset、密码、用户名/邮箱/文件字段、链接、导航、滚动、上传/下载均拒绝。快照每次读取会轮换，动作开始先消费令牌；成功后必须使用返回的新快照，失败则重新读取。会话令牌只存在当前Host进程内存；页面正文与表单值不进SQLite或日志。此源码切片不是操作系统进程沙箱，不包含跨URL导航、登录、表单提交或网站交易能力；离线合成验收不代表真实网站适配。细节见[公开网页静态与隔离动态读取边界](公开网页静态读取边界.md)。

R3.2在此基础上加入`browser.session.navigate.v1`：只有以“导航隔离网页会话：会话ID；快照ID；完整HTTPS公网网址”开头的用户命令可发起导航，目标网址必须由用户直接提供，不从网页链接或模型输出推导。导航消费当前快照令牌，使用与初次打开相同的逐跳HTTPS、公网DNS和重定向校验器重新GET HTML；重定向最多5次、正文最多2 MiB。新页面仍加载到原有sandbox iframe，Context不带Cookie，CSP和浏览器路由继续阻止所有页面子请求、表单、下载和弹窗；不打开用户Edge、不切换前台窗口。成功后返回新网址和新快照令牌；目标失败时不改变原页面并要求用户重新查看以获得新令牌；取消、25秒超时或渲染失败会关闭会话。导航不允许点击页面链接、登录、填写或提交表单，也不代表网站动作已完成。合成测试覆盖页面替换、网址变化、令牌轮换、旧快照重放拒绝及ToolBroker对内网/非HTTPS目标的拒绝；真实网站适配仍待验收。

R3 增加固定下载工具 `browser.download.public.v1`：唯一参数为用户当前任务中明确给出的 HTTPS 公网 `url`，目标固定为 `configured-export`，前置条件必须同时包含 `UserProvidedPublicFileUrl` 与 `ConfiguredFileExportRoot`，预期结果固定为 `PublicFileDownloadedToConfiguredExport`。ToolBroker 经 `ExecuteBackgroundAsync` 调用 `IPublicFileDownloader`，仅将非网页、非可执行/脚本类型的单个文件写入小K数据目录下的 `Exports`。下载器不带 Cookie、不使用系统代理、不读取用户 Edge 会话；TLS仅允许443端口，逐跳重新检查公网 DNS 和重定向，最多5次，45秒总时限、解压后50 MiB上限。文件名经过路径、设备名和危险扩展名检查；临时写入后不覆盖式原子发布，并重新读取核验字节数与 SHA-256。响应正文不送模型或写入任务历史；取消在文件发布前生效，发布后始终完成核验。边界和未验收项见[公网文件下载边界](公网文件下载边界.md)。

R3 增加固定本机压缩工具 `file.archive.single.v1`：唯一参数为当前任务中明确给出的 `source_path`，目标固定为 `configured-export`，前置条件必须同时包含 `ConfiguredSearchRoot` 和 `ConfiguredFileExportRoot`，预期结果固定为 `FileArchivedToConfiguredExport`。ToolBroker 经 `ExecuteBackgroundAsync` 调用 Windows 文件适配器。适配器只读取设置搜索根内不超过100 MiB的单个普通本机文件，在 `Exports` 中创建“原文件名.zip”，ZIP 仅含一个顶层原文件名条目，不接受任意输出路径、不覆盖已有压缩包、不解压或执行。临时 ZIP 会独立读取并核验条目数、名称、长度和内容 SHA-256，再不覆盖地发布并核对归档文件散列；源文件保持不变。取消只在发布前生效，发布后始终完成核验；结果不确定时人工检查，不自动重试。完整边界和验收状态见[本机单文件压缩边界](本机单文件压缩边界.md)。

当前 Windows 文件搜索实现只接受已配置的本机盘符目录，拒绝 UNC 路径和磁盘根目录。目录项通过 [GetFileInformationByHandleEx](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getfileinformationbyhandleex) 的 `FileIdExtdDirectoryInfo` 从已打开的目录句柄枚举，返回布局遵循 [FILE_ID_EXTD_DIR_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_extd_dir_info)；每个子目录和匹配文件再以不跟随重解析点的句柄打开，核对卷序列号、128位文件 ID、最终路径和根边界。单次搜索最多检查 5,000 个目录项并展示 10 条路径；达到任一上限时，结果摘要会明确提示搜索可能不完整或可能还有更多结果。安全检查覆盖摘要边界、搜索根/根内目录联接，以及跨缓冲区枚举。尚未运行对抗性并发重命名/替换压力测试，因此发布验收仍需验证该竞态边界和大目录性能。

本机文本内容位置搜索使用固定工具 `file.search.content.v1` 和参数 `query`，目标为 `user-files`，仅在已配置搜索根内执行。查询最多120字符；只扫描固定文本扩展名，最多递归5层、检查5,000个目录项、读取10个匹配文件，每文件2 MiB、单次合计64 MiB，最多列出10个路径且每文件最多5个行号。适配器用不跟随重解析点的 Windows 句柄验证文件身份、链接数、最终路径和搜索根；读取前后核验身份、长度和修改时间，拒绝不支持编码与文本超限。匹配正文不进入工具结果、任务历史或日志，也不发送给模型；只在当前比对期间短时驻留内存。完整规则和待验收项见[本机文件内容搜索边界](本机文件内容搜索边界.md)。

本机文档摘要使用固定工具`file.summarize.text.v1`，唯一参数为用户命令中的完整`path`，目标为`user-files`，固定前置条件`ConfiguredSearchRoot`和预期结果`LocalDocumentTextExtracted`。只接受配置搜索根内普通本机文件：文本/源码最大64 KiB，DOCX压缩归档最大8 MiB、512个条目、`word/document.xml`最大1 MiB、提取文字最大64 KiB；PDF最大8 MiB、100页、提取文字64 KiB。DOCX仅在内存中解析唯一主文档XML，禁止DTD并关闭外部XML解析器；不访问关系、宏、嵌入对象或其他Office格式。PDF使用固定PdfPig `0.1.16`提取可选择文字，不执行脚本、不读取表单/附件、不做OCR；解析放入仅接收管道数据的低优先级子进程，并先加入512 MiB内存上限和20秒时限的Windows Job Object，建立限制失败即拒绝解析。取消/超时会终止子进程。适配器拒绝网络/链接/特殊项、不稳定读取、超限、损坏和不支持结构。读取结果仅在内存中交给`ModelBroker.RunInteractiveAsync`调用本地模型，最多16段、每段最多6,000字符；JSON正文标为不可信内容，不能作为后续工具授权。任务历史仅保留固定类别，不保存路径或文件正文。完整边界、错误路径和实测未完成项见[本机文档摘要边界](本机文本摘要边界.md)。

只读文件分类工具 `file.classify.preview.v1` 只接受一个配置搜索根内的本机完整目录路径；固定前置条件为 `ConfiguredClassificationDirectory`，结果绑定 `FileClassificationPreviewReturned`。它沿用 Windows 目录句柄和文件身份核验，最多递归五层、检查5,000个目录项；重解析点、访问失败和身份变化均跳过并标示不完整。类别仅由文件扩展名决定，不读取内容、不写入文件、不触发模型。该工具只展示预览，不代表分类移动/复制能力。

`file.copy.v1` 只接受一个位于配置搜索根内的本机完整文件路径，拒绝网络路径、链接、设备、硬链接和备用数据流；单文件上限为100 MiB。目标固定为用户数据目录下的 `Exports`，输出使用源文件名，已存在同名文件时失败关闭，不覆盖。复制先写同目录临时文件，完成后再原子移动并核对字节数和 SHA-256；取消发生在提交前会清理临时副本，提交后若核验失败则标记 `outcome_uncertain` 并要求人工检查，不自动重试。

`file.create.text.v1` 只接受 `file_name` 与 `content` 两个参数，目标固定为用户数据目录下的 `Exports`，前置条件为 `ConfiguredFileExportRoot`，预期结果为 `TextFileCreatedInConfiguredExport`。用户直接输入“创建文本文件：文件名；内容：正文”时才进入此路由；仅允许不含路径的 `.txt` 或 `.md` 文件名，正文最多16,000个字符且UTF-8编码后不超过64 KiB，拒绝无效Unicode与控制字符。适配器在固定导出目录内创建唯一临时文件，刷新后核对路径、长度和SHA-256，再以不覆盖方式发布并再次核对文件身份、长度、内容散列及导出根目录身份。现存同名目标失败关闭；取消只在发布前生效。发布后的核验若无法确认，返回 `OutcomeUncertain` 并要求人工检查，不自动重试。任务历史与结果不保留正文。定向安全检查和全解决方案Release构建已通过；签名打包、安装版和普通界面操作仍待验收。

`file.rename.v1` 只接受配置搜索根内的单个本机普通文件路径和一个新文件名；不接受目录、网络路径、备用数据流、设备、重解析点或硬链接。操作只在原父目录内改名，不移动文件，不覆盖已有文件；Windows 句柄式改名请求固定为不替换目标。执行期间持有源文件及父目录句柄，阻止源项或父目录被并发替换；完成后重新打开目标并核验文件身份、大小、修改时间，且确认原路径已消失。请求发出前取消不产生改动；操作后无法核实时返回 `outcome_uncertain`，要求人工检查，不重试。该动作由用户提供的明确改名指令路由，后台不切换窗口或模拟输入。

`file.move.v1` 只接受配置搜索根内的单个本机普通文件和另一个已配置搜索根内的现存目标目录；只允许同一卷的原子移动，不创建目录、不跨卷复制、不覆盖同名目标。拒绝 UNC、备用数据流、设备、重解析点、硬链接和越界路径。执行时持有源文件、源父目录及目标目录句柄，目标目录句柄不共享删除权限以防检查后替换；使用 `RootDirectory=NULL` 的完整核验路径提交不替换式句柄重命名。提交后重新打开目标并核对文件 ID、大小、修改时间及旧路径消失。请求发出前取消不会改动文件；提交后无法核验则返回 `outcome_uncertain`，人工检查且不重试。该工具只移动一个文件，不提供批量整理；以确定性命令“移动文件：源文件完整路径 到 目标目录完整路径”后台执行，不操作前台窗口。边界细节见[本机单文件移动边界](本机单文件移动边界.md)。

R3 增加固定回收站工具 `file.delete.recycle-bin.v1`：仅有 `source_path` 一个参数，目标必须为 `configured-search-root`，前置条件为 `ConfiguredSearchRoot`，预期结果为 `FileSentToRecycleBin`。确定性命令为“移入回收站：本机完整文件路径”。适配器要求路径在配置搜索根内，并核验单个普通文件、单链接、文件身份、父目录和根目录；拒绝目录、UNC、ADS、通配符、设备、重解析点及超过 Shell 支持长度的路径。准备阶段在内存保存文件 ID、大小、修改时间与目录身份快照；ToolBroker 将规范化完整路径放入非模态任务中心待办，用户明确批准后才执行。审批审计仅持久化固定动作 ID 与 `confirmed`/`declined`，不保存目标路径；任务结果与历史也不含原路径。批准后再次比对身份/元数据与父目录，之后调用 Windows Shell 静默回收站操作并关闭递归与关联文件处理。正常路径只接受 Shell 成功且原位置已消失；失败时若原文件仍在，返回失败；若无法确认状态，则转人工核对且不自动重试。取消发生在 Shell 请求前时不会删除；一旦 Shell 请求已提交，等待结果核验完成。Shell API 以路径执行而非已验证句柄，因此最终核验与调用间存在极短并发替换窗口；不得将其描述成句柄原子删除。SQLite 审计表通过 v5 事务迁移加入动作约束并在迁移前备份。详见[本机单文件回收站边界](本机单文件回收站边界.md)。

## 5. 权限确认协议

外发规则：每次发送前都展示最终平台、经核验的稳定联系人、完整正文和全部附件，并取得用户针对该次内容的明确确认。原始任务指令可以限定目标和内容，但不能跳过预览与确认；正文、目标或附件改变后必须重新确认。模型、通知和网页内容不能授权。发送结果不确定时转人工核对且不得自动重发。当前只有预览，没有实际发送适配器。钱包、付款、交易、凭证不属于概括授权；永久删除、权限变更和管理员操作仍须具体确认。详见[桌宠复用与不打扰执行方案](桌宠复用与不打扰执行方案.md)。

ToolBroker 决定权限与交互模式；模型、RSI、网页不能代替用户授权。后台通知仍只处理核验来源的可见私聊正文；限范围可逆编辑保留快照。`ToolInteractionPolicy` 从固定注册表取得模式。应用启动和窗口切换由`ExecuteAsync`显式用户交互入口处理；文件搜索、代码检索与隔离任务、消息分析/草稿/发送预览统一使用`ExecuteBackgroundAsync`。后台审批和代码审阅通过非模态待办中心显示，不拉前台。空闲恢复队列与真实后台发送仍待接入；未知或需前台的工具由后台入口拒绝，不弹窗、不执行、不重试。

### R1任务历史中的实时审批显示投影

`ILiveApprovalStateProvider`只查询当前Host内存中的审批待办；任务历史投影仅在该任务仍显示`Running`且存在关联的`Confirmation`或`CodeReview`待办时显示`AwaitingApproval`。`MessagePreview`不代表副作用批准，不触发该投影；排队任务和终态不改变。投影只影响读取后的显示模型，不写SQLite，不恢复、不续期或重放审批；进程重启后待办消失，持久历史继续按启动恢复的失败关闭规则处理。审批结果仍必须经ToolBroker和现有一次性审批流程，显示标签本身不构成授权。当前实现见`TaskHistoryDisplayPolicy`、`ApprovalInbox.HasPendingActionConfirmation`和`AssistantRuntime.GetRecentTaskHistoryAsync`。

确认请求由 ToolBroker 生成，`action_digest` 是规范化动作、收件人、最终正文、附件身份/内容摘要、目标与任务 ID 的 SHA-256；如果预览中的任一字段变化，旧确认无效。`approval_id` 一次性使用，默认短时过期；关闭预览等同拒绝。

当前发送预览切片只接受 Host 中用户直接输入的“发送微信给收件人：正文”或“发送QQ给收件人：正文”格式；按用户明确指定的白名单，QQ 仅接受显示名 `K`，微信仅接受显示名 `L`，平台与名称必须严格匹配，其他名称和大小写变体在解析层与 ToolBroker 双重拒绝。该名称来自截图，只是显示名，不是稳定账号身份；因此只允许对应预览，不能据此启用实际发送。提案同时绑定应用 ID、收件人、正文与附件字段，并校验目标为 `<application_id>:<recipient>`。当前只支持无附件预览，显式附件语法会在模型/工具执行前拒绝。WPF 只读预览显示应用、最终收件人、完整正文和附件栏；关闭后返回“发送适配器尚未接入”，不请求外发批准、不写发送审批记录，也不产生外部副作用。真实发送适配器接入前，必须由用户确认的 `K`/`L` 联系人分别绑定到经独立核验的稳定客户端身份，并加入附件身份/哈希校验、变更后重新预览、一次性确认、发送结果核验和 `outcome_uncertain` 人工核对；当前并未实现或验收这些步骤。

    "action_digest": "sha256:eb3142734d9d18e15b25cb6c9f368a2cbbe94e234251d58a270e0fe6c16f8d8a",

ToolBroker 在执行前重读实际收件人、正文与附件文件身份。出现 `ACTION_CHANGED`、`APPROVAL_EXPIRED`、会话锁定或旧目标时停止并重新展示；成功受理批准不等于发送成功。外发操作在崩溃后结果未知时进入人工核对，不自动复用批准。

`LocalInferenceClient` 只接受无凭证、无查询参数的 HTTP(S) 回环地址，禁用系统代理与自动重定向，并限制提示总大小、JSON 深度和响应体大小；因此本机服务返回重定向时调用失败，不会跟随到外部地址。`IInferenceClient` 可选请求参数支持关闭 Qwen 思考模式、JSON-object 模式以及有界 JSON Schema；只读代码说明为 schema 限定 claims、text、citation 字段后，仍由本地解析器独立核对精确字段、源码路径与行号，不把生成格式约束当成语义正确性保证。此请求形状依据固定 llama.cpp b11259 的 [服务端协议](https://github.com/ggml-org/llama.cpp/blob/b11259/tools/server/README.md)；Schema 限于16 KiB对象。普通交互路径不变。响应诊断只提供字符数、token数和结束原因，不含回答/推理正文。接口选项曾通过本机 loopback 假服务检查；真实模型效果仍按[中文编码任务集](../验收与评测/中文编码任务集规范.md)记录，不能据此宣称编程质量达标。`ModelBroker` 以单租约串行化推理调用，交互队列优先于后台队列并限制总排队数；托管 llama.cpp 调用持有运行时租约，空闲4分钟卸载。竞争模型调用必须显式传入独立的 `IManagedModelRuntime`：调度器先卸载主模型和其他最近使用的运行时，再获取目标运行时租约。普通竞争模型在操作结束、失败或取消后卸载；实现 `IIdleRetainedModelRuntime` 的 CPU 语音运行时在成功后安排两分钟空闲卸载，同一模型请求可复用进程；切换运行时仍立即回收，失败路径立即卸载。释放或卸载失败时，调度器进入关闭状态并拒绝后续模型请求。ASR/TTS 的暖模型切换检查已通过；开发版真实 CPU 合成往返冷/暖各两次并匹配2/2。安装版0.1.32.0经包内工作脚本、D盘锁定模型和隔离语音环境完成六句 CPU 合成往返，匹配6/6；另观察到 ASR 空闲121.05秒卸载、重新加载成功，释放后工作进程为0。独立单句重复样本0/3匹配，说明采样结果有波动；报告只保存匿名布尔结果与时延，不含音频或转写。以上不覆盖麦克风、扬声器、噪声或多日资源行为，不能代替语音发布验收。GPU 模式使用 `nvidia-smi` 的空闲/总显存数据，要求模型实测预算之外至少留 1 GiB，并在模型就绪后复查；缺少显存数据或余量不足时拒绝继续并返回 `LOW_VRAM`。Qwen 托管生命周期和 MiMo Q8_0评测 profile已有受控显存样本，但压力、长期、OOM恢复和手动外部服务仍未覆盖，不能据此宣称完整GPU安全验收。ASR/TTS 若需 GPU，也须接入相同资源仲裁。当前模型路由只使用 `primary`；设计可选角色 `complex_candidate`、`decision_candidate`、`vision_candidate`、`asset_generation` 尚未接入模型路由，角色只允许指向本机已安装且完成哈希校验的模型，不能通过请求临时下载权重。首版主模型候选为 Qwen3.5-4B；MiMo Q8_0固定v23管线3/12、JEV-9B Q4_K_M 2/11、Qwen v23 0/11，均未达到80%代码质量门槛且仍隔离在离线评测入口；AutoTrust JEV-9B Q4_K_M编码首筛2/11，低于门槛且仍隔离评测；此结果不验证专用System 1决策头。Qwen-Image-2.1 是研究许可下的图像生成候选，Fara/Laya 不能管理权限。

`decision.choose` 的设计输入是带稳定 ID 的固定候选及可观察上下文，输出只能是候选 ID、`abstain` 和版本信息（当前暂无已验收的决策模型路由实现）。规则先于候选模型；未通过中文任务评估与校准的 Laya/JEV 策略不进入正式路由。TypeSafe Jev 与 `jev-ultrafast` 依赖远端 API，不属于本地首版；JEV-9B GGUF代码评测不能证明专用决策头适用；JEV-9B/27B决策路由仍须另行实现、离线校准和影子评估。任何决策结果仍需 ToolBroker 审核，RSI 不得修改权限或在线更新策略。

`voice.transcribe` 接受一次明确的音频流能力引用，返回文本、时间段和置信信息；`voice.speak` 接受文本引用、语音配置与取消 ID，返回首音时间和完成/取消状态。Host 通过 Windows `MediaCapture` 实现显式点击才开始的 16 kHz 单声道 PCM 内存录音，最长60秒/12 MiB；用户停止后调用本地 ASR，识别内容只填入输入框且不自动执行；播报也须用户点击，提供停播按钮。原始录音不进入 SQLite。

`VoiceInferenceService.TryCreateForWorkspace` 和 `TryCreateForInstallation` 分别接收开发仓库或安装包根、模型目录、Python 环境目录及 `ModelBroker`。安装版约定包内包含 `model-lock/models.lock.json` 与 `voice_worker.py`，外置权重位于设置的 `ModelRoot`，Python 环境位于 `VoiceEnvironmentRoot\asr` 和 `VoiceEnvironmentRoot\tts`。工厂仅验证配置并建立惰性工作进程对象，不启动 Python、加载权重或采集麦克风；推理发生在用户明确触发语音功能后。任何清单、文件或路径校验失败均关闭语音入口并显示状态，不回退到云端。

Host 另有可选的 `WindowsLocalWakeWordListener` 原型：用户在设置明确开启后，MSIX 进程使用 Windows `SpeechRecognizer` 的中文固定列表语法，只接受“嗨小K”“你好小K”“Hi 小K”三个短语；短语结果只触发展开任务面板，随后立即停麦，不自动开始录音、执行工具或外发。识别不到固定短语的文本不传给业务层、不写盘。未安装 MSIX 身份、中文语音识别组件或麦克风权限时失败关闭并显示状态；锁屏、按键录音、停麦和退出会停止监听，按键录音与持续监听不会并行。设置默认关闭；托盘“停麦”会同时关闭并保存唤醒选项。该实现使用 Windows 本地语法约束，不能视作低功耗 KWS/VAD 验收：连续待机 CPU、电量、误唤醒/漏唤醒、设备断开和系统授权仍待实机测量。参见 [Windows 本地语法约束说明](https://learn.microsoft.com/en-us/uwp/api/windows.media.speechrecognition.speechrecognitionlistconstraint?view=winrt-26100) 与[语音识别语言要求](https://learn.microsoft.com/en-us/windows/apps/develop/input/specify-the-speech-recognizer-language)。

## 7. 错误码与重试规则

| 错误码 | 含义 | 默认处理 |
| --- | --- | --- |
| `INVALID_REQUEST` / `SCHEMA_UNSUPPORTED` | 格式或主版本不支持 | 拒绝；记录最小诊断，不猜测字段 |
| `UNAUTHORIZED_CLIENT` | IPC 会话/SID/令牌不匹配 | 拒绝并关闭连接 |
| `PERMISSION_REQUIRED` | 动作需用户确认 | 转 `awaiting_approval`，展示预览 |
| `APPROVAL_EXPIRED` / `ACTION_CHANGED` | 确认过期或预览已变 | 重新生成预览；不可沿用旧批准 |
| `STALE_TARGET` / `TARGET_NOT_FOUND` | 页面、窗口、控件或文件身份失效 | 重新发现；涉及副作用时重新检查权限 |
| `USER_SESSION_LOCKED` / `MICROPHONE_UNAVAILABLE` | 会话或设备不可用 | 暂停，待环境恢复后检查前提 |
| `RESOURCE_BUSY` / `LOW_VRAM` / `MODEL_UNAVAILABLE` | 资源或权重不可用 | 使用已评估降级路径或告知用户 |
| `TOOL_TIMEOUT` / `VERIFICATION_FAILED` | 调用超时或独立核验失败 | 读取实际状态；不可盲目重放 |
| `CANCELLED` | 用户或上层取消 | 停止后续步骤并记录最终状态 |
| `OUTCOME_UNCERTAIN` | 外部副作用可能已经发生 | 阻止自动重试，交用户核对 |
| `EXTERNAL_OFFLINE` | 用户明确启用的外部服务不可用 | 首版不依赖外部模型服务；本地推理故障时明确显示离线，不回退到云端 |
| `INTERNAL` | 未分类内部错误 | 记录脱敏诊断并安全停止 |

仅纯读取、模型生成和明确幂等的操作可按策略自动重试。外发、删除、支付和不可逆编辑即便客户端超时，也先读取外部状态；无法确定就返回 `OUTCOME_UNCERTAIN`。错误码只能描述已观察到的情况，不得把“调用已发送”写成“对方已收到”。

## 8. 版本、迁移与数据处理规则

`protocol_version` 使用 `major.minor`：同一 major 可新增可选字段、事件类型和独立工具 ID；移除必需字段、改变风险语义、状态含义或默认权限需提升 major。接收端可忽略未知可选字段，但必须拒绝未知工具、未知影响等级、缺失关键字段及无法理解的安全枚举。每个工具和 `ActionProposal` 单独以 `.v1` 标识 schema，变更参数语义创建 `.v2`。

完整任务事件和审批溯源的目标记录需携带协议、工具和模型版本。SQLite v6 `tasks`表新增随机HostSessionId，用于判定持久任务是否属于当前Host进程；v5迁移前先备份，并将旧会话的活动任务标记为待核对。v6 `approval_audit` 当前只保存随机记录 ID、固定动作 ID、固定结果和 UTC 时间；不接受自由文本、预览正文、收件人、附件或项目路径。当前记录固定 .NET 验证命令、“应用隔离补丁”和固定单文件回收站动作；只有审计写入成功后才把批准结果交给执行流程。通用确认入口为消息发送准备了固定 ID，但发送适配器尚未接入，因此当前运行不会产生消息发送审计。审批审计只是历史记录，不提供批准恢复、命令重放或自动执行接口。架构升级前先生成一致性备份；v5升至v6时还会将旧Host会话中的未完成任务标记为结果待核对，恢复过程不能重演外部副作用。

偏好与联系人风格必须有来源、更新时间和删除路径；日志只保留脱敏状态、动作、结果及资源指标，不保存密钥、验证码、默认聊天正文、截图或原始音频。

联系人回复风格由用户在本机设置页明确添加，采用固定风格 ID 和联系人名称匹配；未知风格、无效名称和未配置的显式联系人请求均停止，不接受模型自由生成的风格提示。联系人名称只用于本机查找，不传给模型；模型只收到用户本次提供的单条消息和映射后的固定风格指令。当前偏好保存在 SQLite 的 `contact_reply_styles` 表，保留联系人名称、固定风格 ID、用户确认来源和更新时间，设置页可更新或删除。旧设置文件只在一次性事务迁移中读取且迁移本身保持文件不变；迁移标记防止偏好删除后从旧文件再次恢复。旧架构升级前先创建SQLite一致性备份。

## 9. 首版通知与本地编程任务

### MessageNotice.v1

Windows 通知监听器只有在包身份安装并取得用户授权后才可启用。当前 Host 接入的是前台监听器：设置默认关闭，用户可请求权限并填写经核实的通知来源 AUMID allowlist；校验器支持经典桌面应用和包应用标识，最终仍要求精确匹配系统通知的 `AppUserModelId`。启用时建立现存通知基线，后续只处理 Added 变化。事件进入策略组件后先检查系统提供的 `AppUserModelId` allowlist；过滤前不读取 `Notification.Visual`。只有已配置的微信或 QQ 来源可进入对应适配器，其他通知正文不读取、不保存、不送模型。当前私聊/群聊识别尚未由真实样本验证，Host 将其作为未知传给策略；策略会在惰性正文读取器调用之前拒绝自动分析。对策略明确确认的私聊正文，后续 Host 管线会再次核对当前 allowlist、私聊归属、时效与正文长度，再送入有界、仅内存的后台分析队列；交互任务优先。停用监听、用户取消和退出会取消对应任务，正文与模型结果不写入历史或日志。包身份缺失、权限撤销、会话锁定或来源/会话属性不确定时均安全停止。签名 MSIX 已安装；隔离诊断模式已启动并退出，但该模式关闭通知监听且未请求系统授权，因此正式通知授权链路仍未在安装应用中运行验收。

0.1.60.0设置页新增显式一次性来源诊断：仅当通知访问权限已有授权时，枚举最多512条当前Toast的应用显示名和AUMID，过滤可能属于微信/QQ的显示名，在内存中呈现候选。该操作不请求权限、不监听新通知、不访问Toast正文、不保存或自动配置候选、不运行消息适配器或模型。显示名和候选AUMID都不是稳定身份凭证；需由用户结合明确识别的真实客户端通知人工核实。当前普通设置页未在安装版运行，真实来源仍未知。

      "conversation_id": "ephemeral-local-id",

      "is_private_conversation": true,

visible_body 与模型分析只在本次任务的内存中传递。系统通知没有正文时输出“请手动打开会话”，不触发窗口切换。事件记录不得持久化正文、截图或附件。策略层默认使用两分钟、按应用隔离的内存去重，以及每会话每分钟最多十条的自动分析限速；去重和限速键只保存哈希，并有条目上限。该默认值尚未经真实负载校准；适配器的来源、会话判断和实际 Windows 通知接入仍需由 P0 每款至少30条通知验证。

### CodeTask.v1

另提供 `code.inspect.v1` 只读检索动作，使用同一用户选定项目快照和固定模型文件选择步骤，最多读取4个清单内文件、完整源代码上下文最多10,000字符；任务说明逐字点名的清单候选路径优先占用文件预算，路径分隔符只按 `/` 与 `\` 等价规范化后精确匹配。模型返回空数组时只回退到这些明确路径；清单外路径或格式无效仍拒绝。更大的源文件通过受限代码位置索引和最多4个局部片段提供给模型。说明只在本次响应中返回，不持久化答案，不生成补丁、不请求命令审阅或运行命令。检索上下文逐行标注原文件绝对行号；每个回答必须包含引用，且代码校验每个引用的文件和行号都处于本次实际提供的片段内，否则失败关闭。初次回答引用无效时，只允许一次复用同一问题和源码片段的格式纠正；再次无效仍拒绝，不扩大读取范围。引用有效只证明来源位置存在，不替代用户对结论语义的判断。该动作的前置条件为 `ConfiguredProjectAndIsolatedWorkspace`，预期结果为 `CodeExplanationReturned`；错误匹配会在调用模型前拒绝。

CodeTask 状态为 queued、planning、awaiting_approval、running、verifying、applying、completed、failed、cancelled 或 outcome_uncertain。任务只能引用用户选择的 project_id 和隔离 workspace_id；不得接受模型提供的任意根路径。当前代码已接入隔离快照和最多4个既有文本文件补丁。若任务文本明确包含清单内相对路径，则这些文件优先进入4文件预算；文件选择和补丁的相对路径只把 `/` 与 `\` 分隔符差异归一化后与清单精确匹配。空模型选择只回退到任务文本明确点名的候选文件，清单外、重复、格式错误和超出4个明确目标仍失败关闭。完整源代码上下文最多10,000字符；大文件使用受限代码位置索引，纳入 `if`、`switch`、`case` 条件分支和相邻行，模型最多选择4个索引位置后只读取局部片段。补丁编辑接受精确 JSON 字段 `path/startLine/find/replace`；`startLine` 是原文件绝对1起始行号，若提供则必须落在给定片段中且查找文本必须从该行开始唯一匹配，若省略则 `find` 必须在已提供片段和原文件全文各自匹配且在原文件唯一。未知字段、缺失必需字段、重复字段、前后说明文字、代码围栏、片段外或重叠编辑均拒绝，拒绝后不呈现补丁审阅。审阅窗展示完整差异和原项目/隔离工作区路径。用户可保留补丁、单独批准固定 NuGet restore 与 dotnet test 命令，或明确批准将已审阅补丁应用到原项目。应用前重新核验原项目根目录、目标文件基线哈希、隔离工作区根目录和审阅内容哈希；目标变化时整批拒绝。补丁逐文件写入同目录临时文件并用原子替换，失败时只在哈希匹配的情况下回滚；无法确认时持久化 `outcome_uncertain` 并保留应用日志，禁止自动重试。固定命令使用无 shell 的进程参数、仅 nuget.org 的临时 NuGet 配置和工作区内缓存，不接受模型命令或任意参数。两条命令均在 Windows AppContainer 中运行，临时授予任务工作区写权限与固定 .NET 运行时只读权限，并在结束时尝试回收授权和身份；restore 获得 `internetClient` 能力，test 不配置网络能力。构建/测试目标仍可在任务工作区内产生任意文件与子进程；真实项目运行和网络边界尚未实测，因此不宣称所有副作用为零。任务状态和实际限额见[隔离编程代理与工作区](隔离编程代理与工作区.md)。其他命令、成功率评测和本地模型运行验收仍未完成。

动作建议示例：

    {
      "schema": "CodeTask.v1",
      "task_id": "随机UUID",
      "project_id": "用户本次选择的项目",
      "workspace_id": "隔离工作树的短期ID",
      "allowed_actions": ["search", "read", "write_patch", "approved_command", "show_diff"],
      "network_policy": "deny_unless_user_approved",
      "merge_policy": "explicit_user_approval"
    }

执行命令需由本机固定命令ID映射到可审阅命令行，不接受自由shell字符串。项目所需的锁定依赖、运行时与候选模型资产下载，以及必要联网命令，已由用户授权直接执行；执行时仍须限制到声明的来源/版本并核验许可与 SHA-256，不得自动接受新的许可条款。账号消息测试与代替用户外发仍需单独授权。最终 diff 必须留在隔离区供用户检查；修改原项目、提交和推送按仓库阶段开发授权及维护规则执行。

R3 增加固定目录压缩工具 file.archive.directory.v1：唯一参数为用户本次明确给出的 directory_path，目标固定为 configured-export，前置条件为 ConfiguredSearchRoot 与 ConfiguredFileExportRoot，预期结果复用 FileArchivedToConfiguredExport。操作只扫描设置搜索根内的本机普通目录，最多递归5层、5,000个目录项、1,000个文件；单文件不超过100 MiB、总量不超过500 MiB、ZIP不超过540 MiB。拒绝重解析点、链接、特殊文件、越界目录和与 Exports 重叠的根。压缩保留普通文件相对路径，不写入空目录；临时ZIP逐条核对名称、长度和SHA-256，重新扫描源清单后才不覆盖发布。源目录不修改；发布后的不确定结果需人工核对，不自动重试。详见本机目录压缩边界。
