## CPU/GPU 资源与吞吐对照（2026-10-03）

- 可复现命令：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\measure_qwen_benchmark.ps1 -Mode compare -Repetitions 3 -Threads 8`。脚本先对锁定的 Qwen GGUF 和 llama.cpp 55 个暂存文件逐项核对大小与 SHA-256；运行 `llama-bench` 时显式使用 `--offline`、64 个合成 prompt token、32 个生成 token、8 个 CPU 线程、CPU 层数 0 与 GPU 层数 99，各重复 3 次。报告写入 Git 忽略的 `.tools/benchmarks/`，不记录提示或用户内容。
- CPU（8线程）预填充平均 280.81 token/s，标准差 18.56；生成平均 18.84 token/s，标准差 0.18。GPU（请求99层）预填充平均 2535.32 token/s，标准差 339.06；生成平均 95.34 token/s，标准差 0.45。样本数只有3，不能视为 p50/p95 或真实对话端到端时延。
- 500 ms 采样期间，NVIDIA 总显存占用峰值 4,378 MiB、空闲显存最低 3,522 MiB，GPU 利用率峰值 97%、温度峰值 56°C、功耗峰值 67.25 W；`llama-bench` 进程工作集峰值 3,088 MiB、采样CPU峰值33.1%、系统可用内存最低12.21 GiB。测试前显存空闲6,338 MiB，运行前准入阈值为6,024 MiB；测试过程中至少保留3,522 MiB空闲，未触发中止阈值。测试进程退出后无残留 `llama-bench` / `llama-server`，`nvidia-smi` 读数回到约1,563 MiB占用、6,337 MiB空闲的桌面状态。
- 单独以 `-Mode gpu -Repetitions 1 -VerboseDiagnostics` 检查详细日志，llama.cpp 明确报告 `offloaded 33/33 layers to GPU`；CUDA0模型缓冲区2,571.63 MiB，CPU映射模型缓冲区497.31 MiB。这证明这次 `llama-bench` 的99层配置实际全量卸载了33个模型层。单样本只用于核实卸载和缓冲区，不并入吞吐统计。
- 本测量是固定 llama.cpp 微基准，不是小K `LlamaCppModelRuntime` / `ModelBroker` 的端到端请求；它不证明服务冷启动、4分钟自动卸载、取消、长期运行、OOM恢复或最终模型质量。实际服务链路仍只有前述两条合成冒烟记录，运行时仍为 `locally_evaluated`，不能标记为 `accepted`。
