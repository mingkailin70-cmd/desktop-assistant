## CPU/GPU 资源与吞吐对照（2026-10-03）

- 可复现命令：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\measure_qwen_benchmark.ps1 -Mode compare -Repetitions 3 -Threads 8`。脚本先对锁定的 Qwen GGUF 和 llama.cpp 55 个暂存文件逐项核对大小与 SHA-256；运行 `llama-bench` 时显式使用 `--offline`、64 个合成 prompt token、32 个生成 token、8 个 CPU 线程、CPU 层数 0 与 GPU 层数 99，各重复 3 次。报告写入 Git 忽略的 `.tools/benchmarks/`，不记录提示或用户内容。
- CPU（8线程）预填充平均 280.81 token/s，标准差 18.56；生成平均 18.84 token/s，标准差 0.18。GPU（请求99层）预填充平均 2535.32 token/s，标准差 339.06；生成平均 95.34 token/s，标准差 0.45。样本数只有3，不能视为 p50/p95 或真实对话端到端时延。
- 500 ms 采样期间，NVIDIA 总显存占用峰值 4,378 MiB、空闲显存最低 3,522 MiB，GPU 利用率峰值 97%、温度峰值 56°C、功耗峰值 67.25 W；`llama-bench` 进程工作集峰值 3,088 MiB、采样CPU峰值33.1%、系统可用内存最低12.21 GiB。测试前显存空闲6,338 MiB，运行前准入阈值为6,024 MiB；测试过程中至少保留3,522 MiB空闲，未触发中止阈值。测试进程退出后无残留 `llama-bench` / `llama-server`，`nvidia-smi` 读数回到约1,563 MiB占用、6,337 MiB空闲的桌面状态。
- 单独以 `-Mode gpu -Repetitions 1 -VerboseDiagnostics` 检查详细日志，llama.cpp 明确报告 `offloaded 33/33 layers to GPU`；CUDA0模型缓冲区2,571.63 MiB，CPU映射模型缓冲区497.31 MiB。这证明这次 `llama-bench` 的99层配置实际全量卸载了33个模型层。单样本只用于核实卸载和缓冲区，不并入吞吐统计。
- 本测量是固定 llama.cpp 微基准，不是小K `LlamaCppModelRuntime` / `ModelBroker` 的端到端请求；它不证明服务冷启动、4分钟自动卸载、取消、长期运行、OOM恢复或最终模型质量。实际服务链路仍只有前述两条合成冒烟记录，运行时仍为 `locally_evaluated`，不能标记为 `accepted`。

## 托管 ModelBroker 生命周期复验（2026-10-03）

前一节的 llama-bench 只证明固定后端的 CUDA 微基准行为，不等于小K托管服务端到端。本节另记录一次 `ModelBroker` 真实托管链路及资源采样；两种证据不可互相替代。

- 可复现命令：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\measure_qwen_managed_runtime.ps1`。脚本复核锁定的 Qwen GGUF 与 llama.cpp 全部55个运行时文件 SHA-256，使用仓库固定 SDK、离线 NuGet 空源构建诊断器；临时 `llama-runtime.json` 只在不存在时创建，并且仅在内容哈希仍匹配时删除。测试只向 `127.0.0.1` 发送合成提示，不启动 WPF、读取通知或保存模型回答。报告保存在 Git 忽略的 `.tools/benchmarks/`。
- 一次完整链路通过：`ModelBroker` + `LlamaCppModelRuntime` + `LocalInferenceClient`。进程冷启动加首个请求6.28秒；之后10次热请求 p50 2.82秒、最近秩 p95 3.51秒。样本少，只代表本次短提示、单机和当前负载，不能作为稳定的生产 p50/p95。
- 运行中取消在约0.51秒被观察到，随后合成请求恢复成功。最后一次请求后空闲等待262.0秒，健康端点不可达且原进程 PID 已退出；下一请求触发重新加载并成功，耗时7.38秒；再次释放后跟踪 PID 已退出，系统 llama-server 进程数为0。
- 500毫秒资源采样：测试前 GPU 空闲6,315 MiB；运行期间最低空闲3,222 MiB、系统显存占用峰值4,678 MiB、GPU服务器工作集峰值5,084.5 MiB、系统可用 RAM 最低9.89 GiB。整个过程保留超过1 GiB显存；结束后无 llama.cpp 进程，显存回到约1,586 MiB占用、6,314 MiB空闲。
- 这只证明一次受控托管生命周期路径；尚未证明多小时常驻、并发负载、压力下 p50/p95、断电恢复、显存不足/OOM 行为、ASR/TTS竞争模型卸载或回答质量。运行时状态继续为 `locally_evaluated`，不能标记为 `accepted`。

- 使用安装版已配置的锁定 Qwen3.5-4B revision 和相同的 `LlamaCppModelRuntime` / `ModelBroker` / `LocalInferenceClient`，通过现有 `XiaoK.RuntimeDiagnostics` 在 `127.0.0.1:18080` 执行合成探针。共13/13次请求返回非空结果；冷启动首请求9.27秒，10次热请求 p50 3.13秒、最近秩 p95 4.61秒。
