# North Mini Code 本机候选准入评估

评估日期：2026-10-09。用途：判断是否应把近期代码专用模型加入本机候选权重并启动离线评测。本文不代表下载、安装或质量验收。

## 结论

**当前不下载、不部署，也不替换生产模型。** North Mini Code 的代码代理训练方向值得关注，但官方说明的最低硬件为 1 张 H100（FP8 或 FP4）；当前电脑为 RTX 5060 Laptop 8 GB、32 GB 内存，实测资源也不满足项目为模型任务保留的余量。把 3B 激活参数理解为只需存放 3B 权重是不正确的：30B 总参数的权重仍需驻留在 GPU、系统内存或分页存储中。

这项资源准入判断不等于模型质量差，也不关闭未来评估。如果硬件、量化版本或项目资源预算发生变化，应先核验模型文件、许可和固定运行时，再用同一版 40 题本机任务集独立评估；在此之前，Qwen3.5-4B、生产模型配置和 ToolBroker 权限保持不变。

## 官方资料

- Cohere 于 2026-06-09 发布 North Mini Code，标注 Apache 2.0、30B 总参数 / 3B 激活参数、256K 上下文，并定位于代码生成、Agentic 软件工程和终端任务。[Cohere 官方发布说明](https://cohere.com/blog/north-mini-code)
- 同一官方发布说明列出的最低硬件为 1×H100（FP8）或 1×H100（FP4）。这是厂商公布的部署门槛，不等于对所有社区量化格式的独立实测。[Cohere 官方发布说明](https://cohere.com/blog/north-mini-code)
- 官方模型卡要求按 North 的 chat template 组织工具调用，并说明其思考内容与工具调用需按规定格式保留；卡片提供 Transformers 和 vLLM 路线。[CohereLabs 模型卡](https://huggingface.co/CohereLabs/North-Mini-Code-1.0)
- llama.cpp 上游已合入 Cohere2-MoE 架构和 `cohere2moe` 词表支持；这只能说明上游有相应实现，不能替代本机锁定二进制加载该权重的实测。[架构支持 PR #24260](https://github.com/ggml-org/llama.cpp/pull/24260)、[词表支持 PR #24601](https://github.com/ggml-org/llama.cpp/pull/24601)

厂商或模型卡公开基准使用的任务、Harness、采样参数和硬件与本项目固定中文任务集不同，故不折算为小K的40题成功率。

## 本机资源核对

检查时未启动模型或 Host，仅读取 Windows 资源计数器和 NVIDIA 驱动：

| 项目 | 实测值 |
| --- | ---: |
| 可见物理内存 | 31.4 GiB |
| 当前可用物理内存 | 9.4 GiB |
| RTX 5060 Laptop 显存 | 总计 8,151 MiB，可用 6,211 MiB |
| D 盘可用空间 | 320.9 GiB |
| 项目模型任务余量目标 | 至少 8 GiB 系统内存、至少 1 GiB 独显显存 |

按 30B 参数和理想 4-bit 权重作下限估算，纯参数位宽约需 15,000,000,000 字节（约 14.0 GiB）；这还未计量化分组数据、模型元数据、运行时、KV cache 或工作负载。扣除项目保留目标后，本机可分配给新模型的系统内存约 1.4 GiB、显存约 5.1 GiB，不能据此证明 30B 模型可稳定运行。D 盘空间充足不能解决运行时内存不足。

该换算只是权重规模的理论下限；当前没有下载 GGUF/FP4 文件，没有测量真实文件工作集，也没有运行加载、短聊或延迟测试。低比特社区转换不能自动视为上游支持、许可清晰或满足质量门槛。

## 固定运行时与接口差距

本机仍锁定 llama.cpp `0.5.0-dev`（build `11259`，commit `d280808f5`）。本次只读取版本信息；没有尝试加载 North 权重。即使后续量化模型能由该版本读取，仍需验证：模型 chat template、交错思考和工具调用解析、取消和超时、显存/内存准入、独立代码评审、以及与现有 ToolBroker 固定动作提案之间的映射。模型原生的任意终端工具示例不能直接接入小K。

## 下一步

1. 保留 North Mini Code 为“观察候选”，不加入必需模型清单或生产运行目录。
2. 优先继续改善当前受限代理的统一评测和后台工具验收；不同模型、提示和管线的分项成绩不得拼接。
3. 只有当候选锁定格式能够在项目资源余量内稳定冷启动，并完成独立任务评测后，才考虑调整模型选择。编程发布门槛仍为统一40题总体至少32/40、多文件至少7/10、未经授权副作用为0。
