# 语音模型合成往返首测

日期：2026-10-03。结果为单条合成样例的本地 CPU 冒烟，不是 ASR/TTS 质量验收或发布门槛通过证明。

## 可复现步骤

在仓库根目录运行：

```powershell
.\.tools\venvs\tts\Scripts\python.exe tools\verify_voice_roundtrip.py
```

脚本先逐文件复核模型锁清单中的 SHA-256，再用锁定的 CustomVoice 生成 WAV，并将 WAV 字节仅在内存中交给锁定 ASR 工作进程。工作进程使用离线环境和 CPU；未启用 CUDA、麦克风、扬声器，也未把音频写入文件。脚本默认不要求逐字标点匹配；`--strict-transcript` 可检查去标点后的文字是否与固定合成短句一致。

## 本机结果

- Qwen3-TTS-12Hz-0.6B-CustomVoice revision：`85e237c12c027371202489a0ec509ded67b5e4b5`，许可 Apache-2.0；加载约 10.45 秒，合成约 9.95 秒。
- 输出 WAV：24,000 Hz、单声道、3.44 秒、165,164 字节；只驻留内存。
- Qwen3-ASR-0.6B revision：`5eb144179a02acc5e5ba31e748d22b0cf3e303b0`，许可 Apache-2.0；加载约 12.66 秒，转写约 1.72 秒。
- 合成文本为“你好，小K。请打开本地项目。”；ASR 返回“你好，小K，请打开本地项目。”，去标点后匹配。
- 进程按 TTS 完成后再启动 ASR；没有同时加载两个语音模型。两者各只测了一次，未记录受控 CPU/RAM 曲线或多样本 p50/p95。

## 证据边界

本次运行的是 Python 工作进程协议，不是 WPF Host 中的 `VoiceInferenceService`/`ModelBroker` 端到端调用。结果只证明固定权重能在该 CPU 离线环境完成合成与中文转写；不能证明真实麦克风、播放设备、权限提示、取消/故障恢复、噪声环境识别、自然度或实际任务质量。上述项目仍须分别实测。

## 六句CPU离线复测（2026-10-03）

复用锁定的 Qwen3-TTS-12Hz-0.6B-CustomVoice 与 Qwen3-ASR-0.6B，revision、许可和逐文件 SHA-256 与模型锁清单一致。执行命令：

```powershell
.\.tools\venvs\tts\Scripts\python.exe tools\verify_voice_roundtrip.py --strict-transcript
```

脚本在同一个 TTS 工作进程内连续合成六句，再在同一个 ASR 工作进程内转写；六条 WAV 都只在内存中传递，最终仅输出匿名统计与匹配数，不打印识别原文、不保存音频。环境设置 `CUDA_VISIBLE_DEVICES=-1`、Hugging Face/Transformers离线。六句涵盖应用打开、文件检查、取消、安全核对和不确定结果等合成短语。

| 指标 | 本机结果 |
|---|---:|
| 样本数 / 去标点文本匹配 | 6 / 6 |
| TTS模型加载 | 10.59秒 |
| TTS推理 p50 / p95（nearest-rank） | 12.54 / 14.36秒 |
| 输出音频时长范围 | 3.60–4.80秒，24 kHz单声道 |
| TTS实时系数中位数（生成耗时/音频时长） | 约2.99 |
| ASR模型加载 | 12.48秒 |
| ASR推理 p50 / p95（nearest-rank） | 1.11 / 1.63秒 |
| 整机可用RAM：开始 / 最低 | 17,588 / 11,671 MiB（32,189 MiB总物理内存） |
| 系统CPU平均 / 峰值 | 19.5% / 34.4%，217个采样点 |

CPU和可用RAM取自 Windows 全系统计数，包含其他进程活动，不能当成语音工作进程的资源归因；六个短样本的p95也只是初筛统计。该结果证明合成文本回环、基本时延与整机资源变化，不证明音质、噪声或中英混说识别质量。TTS当前约需音频时长3倍的生成时间，不适合作为无需等待的即时播报；GPU加速、Base/CustomVoice对照、真实设备与Host端到端仍待测。首轮实验曾尝试读取启动器PID工作集，发现虚拟环境启动器另派生模型解释器；该约4MiB读数无效，未用于报告。本复测改用全系统计数并明确其归因限制。

## 两轮CUDA TTS对照（2026-10-03）

复用同一锁定模型和六句合成语料，TTS 切换到 RTX 5060 CUDA，ASR 保持 CPU；所有 WAV 仅驻留内存，未启用麦克风/扬声器，不输出或保存识别文本。命令：

```powershell
.\.tools\venvs\tts\Scripts\python.exe tools\verify_voice_roundtrip.py --tts-device cuda --strict-transcript
```

评估器仅在明确指定 `--tts-device cuda` 时允许 CUDA。开始前检查 GPU 空闲显存至少4,524 MiB，并确认没有 llama-server/llama-bench；每0.5秒读取整卡显存，空闲显存低于1,024 MiB或监控失效时只终止本次启动的工作进程。两轮结果如下：

| 指标 | CUDA第1轮 | CUDA第2轮 |
|---|---:|---:|
| TTS加载 / 推理 p50 / p95 | 12.23 / 6.62 / 9.05秒 | 11.04 / 6.79 / 8.66秒 |
| 输出音频时长范围 | 3.28–4.96秒 | 3.60–5.60秒 |
| ASR加载 / 推理 p50 / p95 | 13.51 / 1.08 / 1.78秒 | 13.15 / 1.02 / 1.56秒 |
| 去标点转写匹配 | 5/6 | 6/6（S01–S06均匹配） |
| 整机可用RAM：开始 / 最低 | 17,540 / 12,204 MiB | 17,598 / 12,916 MiB |
| 系统CPU平均 / 峰值 | 12.8% / 55.2% | 11.4% / 70.3% |
| GPU空闲：开始 / 运行最低 / 工作进程退出后 | 6,264 / 3,787 / 6,264 MiB | 6,263 / 3,717 / 6,264 MiB |

相较 CPU 基线 TTS p50 12.54秒，两轮 CUDA p50 快约1.85–1.89倍；但合成仍慢于音频实时播放（约1.67–1.75倍时长）。ASR仍在 CPU。TTS 的锁定 `generation_config.json` 设置 `do_sample=true`、temperature 0.9、top-k 50，因此采样结果会波动：两轮分别5/6和6/6，不足以判定转写稳定性。首轮未输出逐句布尔掩码；转写原文和音频均未保存，无法事后定位那一条，第二轮只报告 S01–S06 全匹配。显存余量高于1 GiB保护线，且工作进程退出后恢复到基线附近；GPU/CPU/RAM 均为系统级采样，不能归因到小K以外的进程。

该对照只验证指定硬件、锁定权重和短合成样本下的 CUDA 推理及资源保护路径，不代表 TTS 候选通过验收。后续需固定评测随机种子或扩充重复样本，比较 Base/CustomVoice、听感和实际首音延迟，并接入 Host/ModelBroker 后验证取消、释放与长期运行。

## CPU 语音暖模型复用与冷/暖对照（2026-10-04）

`PythonVoiceModelRuntime` 现在实现 `IIdleRetainedModelRuntime`：一次语音请求成功后，进程可在内存中保留两分钟，定时关闭时回收进程树和模型文件句柄。`ModelBroker` 跟踪最近使用的模型，启动不同运行时之前先立即卸载前一个；普通竞争模型仍在请求完成、失败或取消时卸载。语音工厂仍只在用户明确发起语音操作时创建模型进程，且持续强制 CPU/离线。
