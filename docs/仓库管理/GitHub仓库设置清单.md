## 建议由仓库所有者在 GitHub 页面设置

- 保持 `main` 为默认分支。
- 添加以 `main` 为目标的 Ruleset：禁止删除、禁止强推；不要求必须通过 PR 或预先通过状态检查，以保留阶段性直接推送流程。无需为这两条限制单独设置绕过角色。
- 在 Settings → Actions → General 中将工作流令牌默认权限设为只读；当前工作流本身也显式限制为 `contents: read`。
- 开启私密漏洞报告（如果账户/仓库页面提供此选项）；保留 Issues。Discussions 按维护需要选择。
- Issue 表单使用 `bug` 和 `enhancement` 标签；当前连接器未能核验标签列表，需在仓库页面检查，如缺失再创建。
- 选择并添加项目许可证前，README 会继续说明目前未授予代码复用许可；公开仓库不等于开放许可。

本机 Release 构建和安全检查通过不代表 GitHub Actions 运行通过。最近三次阶段推送后的 CI 状态需在 GitHub Actions 页面另行核验；不要引用旧提交的 Actions 结果代表当前提交。

不要启用“必须经 PR 合并”或“必须先通过状态检查”作为 main 的推送门槛，否则会挡住已约定的阶段性直接提交。若以后改为 PR 发布，再调整 Ruleset 与流程。
