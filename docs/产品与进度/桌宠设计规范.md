## 1. 设计目标

小K平时是一个安静、可辨认、可随时召出的桌面伙伴；接到任务后，要让用户一眼看懂它是否在听、在想、在操作电脑、在等待确认，以及能否停止。外观服务于状态表达，不用持续动画吸引注意力。

设计优先级：操作状态清楚 > 可控和隐私感 > 易读易用 > 角色表现。视觉方案可在制作素材时调整，但下面的交互含义和安全提示应保持稳定。

## 2. 界面组成与布局

| 区域 | 主要内容 | 行为 |
| --- | --- | --- |
| 桌宠 | 3D角色本体、轻量状态胶囊、名称提示 | 透明无卡片底板；可拖动；单击猫咪展开任务卡；右键打开菜单；不在屏幕中央长期遮挡工作。 |
| 托盘入口 | 当前状态、麦克风开关、打开面板、退出 | 桌宠隐藏或窗口被覆盖时仍能操作。 |
| 任务卡 | 用户原话、拟做的事、当前步骤、核验结果、取消 | 仅在唤起或执行期间展开；长任务可以收起，进度仍可从托盘查看。 |
| 确认框 | 目标、收件人、最终文字、附件、风险和确认按钮 | 对外发送、删除、支付、管理员动作必须展示完整预览；确认框不因倒计时自动同意，批准过期时禁用确认并提示重新核对。 |
| 文本输入 | 输入命令、查看转写、修正识别 | 唤醒失败、嘈杂环境和无麦克风时使用。 |

桌宠可拖动到屏幕边缘并记住位置；多显示器、缩放比例和分辨率变化后，位置要重新限制在可见区域。可提供“始终置顶”“仅在任务时显示”“隐藏桌宠，仅保留托盘”等选项，默认不强制置顶。任务卡应避开任务栏和屏幕边缘；重要确认框居中显示且可通过键盘操作。桌宠收起态使用无卡片底板的透明窗口，让三维银渐层小猫成为主视觉；v15 猫咪后方使用低对比鼠尾草绿柔光和贴地阴影，上方状态胶囊显示简短状态并可悬停查看完整详情，下方小标签显示“小K”和操作提示。点击猫咪展开任务卡，任务卡顶部复用同一素材作为头像并提供欢迎文案。当前窗口为 300 × 372 DIP，源码素材为 `xiaok-silver-shaded-3d-v15.png`，展示尺寸为 284 DIP。v14 MSIX `0.1.39.0` 是历史安装版本；当前 `0.1.40.0` 已包含 v15。原生窗口截图、透明合成边缘、不同缩放比例、多显示器及高对比度验收仍待完成。

布局使用 WPF 的设备独立像素（DIP）：当前桌宠收起态为 300 × 372 DIP，任务卡默认 500 × 650 DIP；窄屏时不得超出可用工作区，主要按钮点击区域至少约 40 × 40 DIP。后续可在不同缩放比例和屏幕上调整尺寸。

## 3. 视觉语言

- **形象**：采用可爱、柔和的 3D 银渐层小猫，银白绒毛、深银虎斑、翠绿大眼、粉色鼻子、鼠尾草绿项圈和银色星形吊坠。角色外观参考 v15 全身正面坐姿PNG；正式Host源码现使用原创WPF三维网格表达相同身份，并有待机、聆听、思考、执行四种静态姿态。面板头像和渲染失败回退仍使用PNG。小尺寸下须清楚辨认，状态表情只作补充。三维源码尚未进入签名安装版，桌面实机观感与透明合成待验收。
- **配色**：界面基础色跟随系统浅色/深色模式；状态使用稳定语义：蓝色表示聆听，紫色表示规划，青色表示执行，琥珀色表示等待确认，绿色表示完成，红色表示失败或被阻止。颜色必须配合文字或图标。
- **字体与尺度**：优先系统中文字体；任务正文至少达到系统默认可读尺寸，支持 Windows 文本缩放。短标签不使用缩写代替完整状态。
- **层级**：桌宠小而轻，任务卡中等，确认框最显著。模型名称、显存等技术细节放到“详情/诊断”，主界面只显示用户需要判断的动作、对象和结果。
- **麦克风提示**：录音状态要有持续可见的文字或图标提示，并能从桌宠、任务卡或托盘关闭麦克风。

## 4. 状态与动效

内部任务状态遵循[实施计划与模型选型](实施计划与模型选型.md)中的 `Idle → Listening → Planning → AwaitingApproval → Executing → Verifying → Speaking/Done`，界面文字与动作对齐：

| 状态 | 用户可见文案示例 | 形象与操作反馈 |
| --- | --- | --- |
| 空闲 | “小K待命” | 静止或极低频呼吸动效；没有持续旋转光效。 |
| 聆听 | “正在听 · 点击停麦” | 小幅波纹；转写文本可见并可改。 |
| 规划 | “正在整理步骤” | 轻微思考动作；超过短暂等待时显示正在处理的阶段。 |
| 等待确认 | “请确认发送内容” | 停止自动执行，突出预览与“取消”；角色不以表情催促确认。 |
| 执行 | “正在打开 VS Code” | 低频进度动效；显示目标和可取消入口。 |
| 核验 | “正在确认窗口是否打开” | 与执行状态区分，避免把“已尝试”说成“已完成”。 |
| 完成 | “已打开，并找到项目窗口” | 一次短反馈后回到安静状态。 |
| 失败/取消 | “未完成：未找到窗口”或“已取消” | 明确原因与下一步，停止持续动效。 |

动效原则：状态切换要短、可中断；执行中不依赖无限循环动画表示进度；TTS 播放时角色口型只表示“正在说话”，不暗示任务成功。支持系统“减少动态效果”；开启后以静态图标与文案替代非必要动画。音效默认克制，可分别关闭唤醒、执行完成、错误提示，且所有声音都有视觉对应。

面板头像与桌面回退素材为 `src/XiaoK.Host/Assets/Pets/xiaok-silver-shaded-3d-v15.png`，运行时直接加载本地资源，不调用绘图模型。正式Host桌宠主体由本地WPF三维网格生成；收起态下方使用鼠尾草绿猫爪标记和操作提示，角色后方保留低对比柔光与贴地阴影，展开面板使用暖白、鼠尾草绿主题。四种网格姿态仅在状态变化时切换，不运行常驻循环动画；TTS口型、等待确认表情及完成/失败反馈尚未实现。签名安装版还未更新到该渲染器，透明桌面、不同背景、缩放、多显示器、高对比度、CPU/GPU资源和锁屏恢复仍待验收。计划中的非必要动画应遵循减少动态效果、窗口不可见或锁屏时暂停等约束。

## 5. 主要交互路径

1. 用户通过快捷键或文本唤起；可选唤醒词原型只在设置显式开启后监听。识别到固定短语后，小K只展开面板并停麦，不自动采集任务语音。用户需要再点击语音按钮开始录入，或直接用快捷键/文本。
2. 用户给出任务。语音转写可在执行前检查；含歧义的目标由小K提出简短澄清。
3. 小K在任务卡展示目标与计划。普通低风险步骤可以继续，涉及确认的动作进入等待状态。
4. 执行期间显示当前动作、对象和取消入口。每一步完成后读取实际窗口、文件或网页状态。
5. 只有核验成功才报告“完成”；未核验成功时说清已尝试什么、目前看到什么，以及可以怎样重试。

消息界面要把通知中可见原文、“可能的理解”和“建议回复”分开；发送预览显示最终收件人、完整文字和附件。微信/QQ通知正文不可见或私聊归属不明时，提示用户手动打开会话，不自动切换窗口。模型离线时明确提示本地服务未启动，不回退到云端。

## 6. 权限与错误反馈

固定权限规则由工具层执行，界面负责让决定可见：

- 自动完成：启动应用、切换窗口、读取用户明确指定的信息。
- 范围内编辑：说明编辑对象，允许取消并保留可恢复信息。
- 明确确认：对外发送、删除、支付、管理员操作。默认焦点放在取消或关闭，不预选确认；确认后仍需核验真实结果。
- 拒绝或失败：用自然语言说明原因，保留可查看的技术详情；不循环重试同一个可能造成重复效果的动作。

始终提供全局“停止执行”和“停麦”。确认框出现时，唤醒词或模型生成的文字不能代替用户确认。对于无法判断的界面状态，小K应停下来请求用户接管。

## 7. 无障碍与低资源约束

- 任务卡、确认框和托盘命令支持键盘导航、可见焦点及屏幕阅读器标签；状态不只靠颜色、声音或角色表情传达。
- 支持文字输入、文字输出和静音模式；语音能力不能成为使用小K的前提。
- 跟随 Windows 文本缩放和高对比度设置，避免在透明背景上出现低对比文本。
- 空闲桌宠静止或低帧率、暂停后台不可见动画；不因角色素材持续占用独显。桌宠 Host 优先集显，推理进程按需使用独显，实际 GPU 归属安装后复核。
- 空闲时小K新增显存低于 300 MiB 是待测目标，不能在视觉设计中引入需要常驻的大型生成模型。大模型空闲约 3–5 分钟卸载，由 `ModelBroker` 管理。

## 8. 设计验收

P1 用空闲与长时运行验证遮挡、多屏定位、键盘操作、停麦/取消和资源目标；P2 验证唤醒、转写与播报反馈；P3 验证任务预览、逐步核验、失败恢复及未经确认不会外发或删除。角色素材和动效只有满足这些条件后才作为可发布版本的一部分。
