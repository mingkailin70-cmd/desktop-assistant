更大模型的量化版可能在复杂编程和多步推理上优于小模型，但结果取决于量化位宽、指令微调方向、模板兼容和任务类型；低比特压缩会带来质量损失，参数规模或社区榜单不能单独决定选型。对本机32 GB RAM、RTX 5060 Laptop 8 GB，27B Q4权重大约16–19 GB，无法整装进显存，必须混合卸载且会争用系统内存带宽。因此它是空闲资源充足时按需启动的“复杂任务候选”，不是长期驻留主模型。

官方当前提供的Qwen3.8型号为Qwen3.8-27B，原生支持图像/视频输入并强调多步代理任务；本机可比较社区Pi微调、GSQ-RCO与普通GGUF量化，但它们的校准集、格式和位宽不同，文件体积从约8.4 GiB的已锁定GSQ IQ2_XS到常见Q4约17–19 GB不等，不能只看“27B”或跑分判胜。Q2/IQ2属于低位宽质量风险候选，须等可用RAM达到锁定门槛后再做同题实测。[Qwen3.8官方模型卡](https://huggingface.co/Qwen/Qwen3.8-27B)、[社区GGUF量化目录](https://huggingface.co/Distillio/Qwen3.8-27B-GGUF)

本阶段按以下顺序比较民间公开的实现与权重，模型卡的分数只用于确定筛选优先级：

1. **编程专用质量线：Qwen3.8-27B-pi Q4_K_M。** SFT+GRPO社区微调的固定revision与文件散列已登记；此前下载的本机权重目录在2026-10-14盘点时已不存在，锁状态为`candidate`。只有重下并复核后才能评测小K隔离代码任务中的检索、多文件补丁、工具反馈修复和失败恢复。它最贴近编程代理用途；必须和同底模基础量化控制组分开看，且不能把Pi自身 benchmark 当本机结果。GitHub社区推理项目`signalnine/q27`记录了该微调的重新打包方式和作者12实例对照，但该对照使用自有运行栈/代理条件，不能代替小K任务评测，也不能据此认为权重兼容固定llama.cpp b11259。[社区模型卡](https://huggingface.co/bytkim/Qwen3.8-27B-pi-GGUF)、[GitHub重打包与作者对照](https://github.com/signalnine/q27)
2. **同底模量化线：GSQ-RCO IQ3_S、已锁定IQ2_XS及普通Qwen3.8 Q3/Q4。** IQ3_S是更高位宽的下一优先候选，但尚未下载和锁定；IQ2_XS固定revision与散列仍留在锁清单，但本机权重目录在2026-10-14盘点时已不存在，锁状态为`candidate`，需重新下载并复核后才能作为本地对照。待达到RAM/显存门槛后，在同一运行时、上下文和工具设置下比较任务质量、延迟、峰值资源与中断恢复。IQ3_S发布方基准仅用于候选筛选，不能替代小K本机40题结果。[GSQ实现](https://github.com/IST-DASLab/GSQ)、[权重卡与量化报告](https://huggingface.co/ISTA-DASLab/Qwen3.8-27B-GSQ-RCO-GGUF)
3. **高密度路线：Ternary Bonsai 2 27B。** 已接入专用Prism候选并完成短时格式冒烟；量化格式与运行时不同，成绩需独立报告，不与llama.cpp直接混算。现有短测约2.9 token/s，只证明单轮可以返回，不足以支持日常使用；优先检查任务质量、首字延迟、交互让位和长任务稳定性。[运行项目](https://github.com/PrismML-Eng/Bonsai-demo)、[权重卡](https://huggingface.co/prism-ml/Ternary-Bonsai-2-27B-gguf)

6. **桌面视觉理解研究线：GELab-Zero-4B-preview。** GitHub提供GUI Agent工程，配套模型是Qwen3-VL-4B的中英微调权重，模型页标Apache-2.0；上游报告主要面向Android应用、ADB、截图与坐标动作。[GitHub项目](https://github.com/stepfun-ai/gelab-zero)、[模型卡及底模/许可](https://huggingface.co/stepfun-ai/GELab-Zero-4B-preview)。仅作为本地视觉理解候选：可以先在资源门槛允许时评估合成/脱敏截图中的控件识别和页面状态理解；不采用它的Android执行层、点击坐标或多设备任务分发，也不将其视作Windows后台控制能力。权重未下载，Windows不抢焦点能力、RAM/显存峰值和小K中文桌面任务质量尚未验证。

### 资源准入与淘汰规则

- 不为跑大模型而关闭用户正在使用的程序。27B Q4仅在即时可用RAM达到18 GiB、独显空闲至少4,524 MiB时做受限短测；GSQ-RCO IQ2_XS需即时可用RAM至少15 GiB并满足相同显存线。运行中保持至少1 GiB独显和4 GiB系统内存余量，触线立即停止候选任务并释放模型。
- 先固定每个候选的模型revision、权重SHA-256、许可证、模板、运行时、量化、上下文长度和评测程序身份，再跑兼容/资源冒烟；通过后才进统一40题代码集。另记任务成功、补丁可应用、工具反馈修复、中文遵循、首字/p50/p95、token数、RAM/VRAM峰值和取消响应。未通过资源门槛不得启动；未通过质量门槛不得作为生产模型。
- 基础量化、微调、蒸馏和专用量化格式使用独立候选ID与完整结果，不拼接跨版本、跨运行时或不同题集的分数。当前生产模型及ModelBroker策略不变；27B仅能在空闲时按需加载，不能与另一个大型GPU模型并驻。

## 2026-10-13 社区 JEV/System 1 本地权重路线

Jev 的开源集成代码不等于 Jev 模型权重开放。`browser-use/jev-ultrafast` 是 MIT 许可的浏览器操作示例，但其决策调用依赖 TypeSafe 托管 Jev，文本生成还需另一个模型服务；不纳入小K本地推理链路。可以借鉴“有限选项直接打分、同时挑选动作和目标、只在需要输入文字时调用生成模型”的结构，实际动作仍必须经过本地 ToolBroker。

## 3. 总体结构

桌面用户入口调用 Voice 与 TaskOrchestrator；编排器连接本地 ModelBroker、规则优先的 DecisionProvider、固定 ToolBroker 与本地存储。ToolBroker 仅连接 Windows/文件/UIA、Edge DOM/ARIA、微信和 QQ 通知适配器，以及隔离 CodeAgent。脱敏评测样本由用户另行同意后保存。

- XiaoK.Host：.NET 10 + WPF，托盘、桌宠、文本/快捷键、麦克风状态、任务取消和审批预览。运行于当前登录用户，不做 Windows 服务桌面交互。
- XiaoK.Voice：ASR/TTS在独立工作进程按需运行；共享Sherpa CPU KWS检测器已由Host可选AudioGraph采集适配器调用。默认唤醒关闭、Windows引擎仍为默认；Sherpa为实验候选，定制词识别率、VAD、常驻资源和设备异常恢复尚未验收。
- XiaoK.Inference：本地模型客户端与 ModelBroker；仅连 127.0.0.1 或用户 SID 受限的本机 IPC，不接受公网 endpoint。
- XiaoK.Tools 与 XiaoK.Adapters.Windows：结构化动作注册、参数/范围/目标验证、执行和独立核验。
- XiaoK.Storage：任务、步骤、用户认可的偏好和可删脱敏样本。首版发布前使用 SQLite 和迁移/备份；原始通知正文默认不持久化。
- CodeAgent：本地模型驱动，仅在用户选择的项目副本或隔离 worktree 内搜索、读取、提出补丁并运行已批准的本地命令。不能读凭证、越界写、删除、Git push 或未经同意联网。

所有模型输出和外部文本均不可信。模型提出 ActionProposal，ToolBroker 按 schema、权限、目标新鲜度和前置条件检查后执行，并独立核验结果。发送、删除、支付、管理员操作需确认。权限规则不可由模型、RSI或网页内容调整。

## 5. 通知与消息安全

MSIX 应用声明 Windows UserNotificationListener 能力，首次启用通知监控前显示用途并请求 Windows 授权。通知访问可能覆盖其他应用，因此接收事件后先用系统提供的发布者 AppUserModelID 对照微信/QQ allowlist；其余通知必须立即丢弃，不记录也不传模型。

两款适配器各自负责发布者身份、私聊/群聊判别、去重和限速。无法可靠识别私聊时不得自动分析。只将通知中可见正文送到本地模型，任务完成后释放正文；不把通知当成完整聊天上下文。没有正文、系统权限撤销、会话锁定或来源/私聊不明时，暂停自动分析并准确提示。正文缺失只提醒用户自己打开应用，不自动切换窗口。

发送动作需按收件人、完整文字、附件名/身份摘要和操作目标生成一次性预览。用户确认后再执行，执行前重新核对目标和附件。当前接收人白名单为 QQ 显示名 `K`、微信显示名 `L`，其他名称或平台错配一律拒绝；显示名不是稳定账号身份，实际发送适配器接入前必须先独立核验联系人身份。任何外发内容仍需逐条展示并取得用户确认。结果超时或状态无法读取时标记 outcome_uncertain，等待人工确认，不重试。

## 7. P5–P6 后续研究

- P5：同任务集比较 MiMo 9B、JEV-9B；JEV-27B、OpenJev、Laya、Fara 与未来 Qwen 型号仅在许可/资源允许时做离线研究。发布后再研究 RSI。研究结果只能选预定义候选动作，权限始终由确定性 ToolBroker 裁定。
