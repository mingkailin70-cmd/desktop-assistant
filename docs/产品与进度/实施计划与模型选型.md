# 小K首版实施计划、架构与模型选型

环境版本候选进一步固定为：Python 3.12 x64；ASR 使用 qwen-asr 0.0.6 / Transformers 4.57.6，TTS 使用 qwen-tts 0.1.1 / Transformers 4.57.3，分别创建独立 venv；PyTorch 2.14.0 + cu132 是 CUDA 测试候选。以上不是已安装状态；传递依赖哈希及本机兼容结果仍待授权下载后锁定。

更新：2026-09-30。本文只写当前冻结的方案与验收目标；尚未取得的本机证据不能表述为已通过。

详细的进程边界、任务和通知数据流、模型资源调度与目标目录见[整体架构与项目结构](../架构与接口/整体架构与项目结构.md)。每个模型文件、运行时版本、Python 环境、SHA256、D 盘安装、升级和回滚方案见[模型权重与环境部署方案](../开发与发布/模型权重与环境部署方案.md)。上述文档是下载前规格；模型权重和依赖未安装。

当前主模型决定仍是候选：Qwen3.5-4B 官方仓库为 Transformers Safetensors，不是本计划中笼统写的“Q4 权重”；Q4_K_M GGUF 是衍生转换文件，必须锁定具体 revision、转换来源、模板/视觉投影及本机 SHA256 后验收。运行候选为 llama.cpp b11256（commit c85b92c），CUDA 13 资产需与本机 Driver 596.49 实测兼容。ASR/TTS 采用官方 0.6B 权重的隔离 Python 3.12 环境候选；MiMo 9B 权重约 18.8 GB，仅作为 CPU/部分卸载对照测试，不作为 8 GB 独显常驻模型。具体文件和边界见部署方案。

## 1. 首版目标和固定边界

小K是登录后运行在当前用户会话的 Windows 桌宠和个人助手。首个可用版本以六类任务全部可验收为门槛：

1. 打开应用并核验目标窗口。
2. 在允许的本地范围内找文件。
3. 用本地模型在用户选定的隔离工作区完成编程任务并给出 diff。
4. 基于微信/QQ交给 Windows 的单条私聊通知，区分事实与可能意图。
5. 按用户确认过的联系人风格起草回复。
6. 发送消息或附件前展示收件人、正文和附件，用户明确确认后再发送。

开发任务由本地模型完成，不调用 Codex。模型推理没有云端回退。微信与 QQ 同时纳入首版：关注两款应用的全部新私聊通知；仅有正文、来源身份可核验、私聊归属确定、通知权限有效且用户会话解锁时，才自动进行本地分析。通知缺正文时只提示用户手动打开会话，不切换窗口。不得读取微信/QQ客户端数据库、注入进程或模拟非官方协议。外发一律需要最终预览和明确确认。

安装、登录启动、长时间运行、工作进程恢复与回滚属于首版交付，而非后期研究。Laya/Fara/Jev/RSI 只在发布后研究，不改变固定权限策略。

## 2. 本机与资源策略

目标 PC：Intel Core Ultra 9 275HX、32 GB RAM、RTX 5060 Laptop 8 GB、Intel 集显。独显显存应至少保留约 1 GiB；这需要在当前后台负载下逐次测量，不能把单次 nvidia-smi 当常量。小K空闲新增独显显存目标低于 300 MiB，属于待测发布指标。

| 状态 | 常驻与模型策略 |
| --- | --- |
| 空闲 | WPF Host、托盘、快捷键、CPU 唤醒词/VAD；不驻留大模型。目标 3–5 分钟空闲后释放模型。 |
| 交互 | 唤醒、ASR、对话模型和TTS按需执行；ModelBroker一次只加载一个大型GPU模型。 |
| 编码 | 本地代理运行于隔离工作区；每个工具步骤结束后可让位于交互请求，不允许后台霸占显存。 |
| 看屏幕 | 优先使用应用API、UIA、DOM/ARIA和OCR；只有结构信息不足才按需用视觉模型。 |
| 生成形象 | 只在制作素材时启动图像模型，生成后退出，不作为桌宠常驻依赖。 |

模型、推理运行时、缓存、用户数据库和可删除评测样本放在 D 盘仓库外，例如 D:\XiaoK\Models、D:\XiaoK\Cache、D:\XiaoK\Data、D:\XiaoK\Evaluations。数据路径应可配置；Git 忽略规则覆盖权重、个人设置、日志与运行数据。

## 3. 总体结构

桌面用户入口调用 Voice 与 TaskOrchestrator；编排器连接本地 ModelBroker、规则优先的 DecisionProvider、固定 ToolBroker 与本地存储。ToolBroker 仅连接 Windows/文件/UIA、Edge DOM/ARIA、微信和 QQ 通知适配器，以及隔离 CodeAgent。脱敏评测样本由用户另行同意后保存。

- XiaoK.Host：.NET 10 + WPF，托盘、桌宠、文本/快捷键、麦克风状态、任务取消和审批预览。运行于当前登录用户，不做 Windows 服务桌面交互。
- XiaoK.Voice：CPU 唤醒词和轻量 VAD 常驻；ASR/TTS 在独立工作进程按需运行。
- XiaoK.Inference：本地模型客户端与 ModelBroker；仅连 127.0.0.1 或用户 SID 受限的本机 IPC，不接受公网 endpoint。
- XiaoK.Tools 与 XiaoK.Adapters.Windows：结构化动作注册、参数/范围/目标验证、执行和独立核验。
- XiaoK.Storage：任务、步骤、用户认可的偏好和可删脱敏样本。首版发布前使用 SQLite 和迁移/备份；原始通知正文默认不持久化。
- CodeAgent：本地模型驱动，仅在用户选择的项目副本或隔离 worktree 内搜索、读取、提出补丁并运行已批准的本地命令。不能读凭证、越界写、删除、Git push 或未经同意联网。

所有模型输出和外部文本均不可信。模型提出 ActionProposal，ToolBroker 按 schema、权限、目标新鲜度和前置条件检查后执行，并独立核验结果。发送、删除、支付、管理员操作需确认。权限规则不可由模型、RSI或网页内容调整。

## 4. 模型与运行时计划

| 能力 | 首测选择 | 备选/条件 |
| --- | --- | --- |
| 主对话与工具规划 | Qwen3.5-4B Q4，固定转换/量化文件哈希 | 先测 4K 上下文，再测 8K；如质量或速度不达标，用同一任务集比较。 |
| 推理运行时 | 固定版本 llama.cpp Windows 构建 | 只绑定回环地址；关闭其任意 shell/实验 agent 工具，使用自有 ToolBroker。 |
| 语音识别 | Qwen3-ASR-0.6B | 按官方要求建立隔离 Python 3.12 环境；CPU延迟不达标再比 sherpa-onnx 轻量模型。 |
| 语音合成 | Qwen3-TTS 0.6B 系列 | 与主模型错峰；CPU速度、首音延迟不达标时测 sherpa-onnx。 |
| 复杂编码候选 | MiMo-V2.6-Distill-Qwen-9B | 只做按需及部分CPU卸载实验；需要保持至少约1 GiB独显余量。 |
| 常驻唤醒/VAD | sherpa-onnx CPU KWS/VAD | 通过房间实录评估误唤醒和漏唤醒。 |
| 生成式视觉素材 | Qwen-Image 新版候选 | 只在开发/素材阶段按需运行；先确认许可证、低显存路径和结果。 |

模型排名或宣传分不能替代本机实测。记录来源、许可证、运行时版本、模型哈希、量化、上下文、中文任务成功率、p50/p95、RAM/VRAM和冷启动。用户尚未逐项确认下载模型/运行时依赖，因此当前没有下载权重或第三方运行时。

## 5. 通知与消息安全

MSIX 应用声明 Windows UserNotificationListener 能力，首次启用通知监控前显示用途并请求 Windows 授权。通知访问可能覆盖其他应用，因此接收事件后先用系统提供的发布者 AppUserModelID 对照微信/QQ allowlist；其余通知必须立即丢弃，不记录也不传模型。

两款适配器各自负责发布者身份、私聊/群聊判别、去重和限速。无法可靠识别私聊时不得自动分析。只将通知中可见正文送到本地模型，任务完成后释放正文；不把通知当成完整聊天上下文。没有正文、系统权限撤销、会话锁定或来源/私聊不明时，暂停自动分析并准确提示。正文缺失只提醒用户自己打开应用，不自动切换窗口。

发送动作需按收件人、完整文字、附件名/身份摘要和操作目标生成一次性预览。用户确认后再执行，执行前重新核对目标和附件。结果超时或状态无法读取时标记 outcome_uncertain，等待人工确认，不重试。

## 6. P0–P4 里程碑与发布门槛

| 阶段 | 交付与退出条件 |
| --- | --- |
| P0 可行性闸门 | 每款应用至少30条后台可见正文私聊通知；按身份正确过滤、识别私聊、去重并触发本地分析比例≥95%。按[中文编码任务集规范](../验收与评测/中文编码任务集规范.md)建立约40条任务并保存在仓库外；完成本机评分后再判断代码质量门槛。另建语音/桌面任务集，测模型质量、语音延迟和GPU余量。任一应用通知正文不可用时记录样例并重新决定方案。 |
| P1 常驻交互 | 桌宠、托盘、文本/快捷键、登录启动、取消、停麦、设置和故障状态；Host崩溃或工作进程退出时停麦仍有效。空闲新增dGPU显存<300MiB并记录CPU/RAM。 |
| P2 离线语音与模型 | CPU唤醒、VAD、ASR、主模型、TTS；断网基础交互可用，模型推理无云回退。记录端到端延迟、误唤醒/漏唤醒和资源。 |
| P3 工具与隔离代理 | 应用、文件、浏览器工具，微信/QQ通知适配器，安全审批；内部先打通“打开VS Code项目并核验”。编程任务覆盖检索、单文件、多文件、失败修复，整体完成率≥80%，多文件≥70%。越界写、未批准联网、未确认外发均为0。连续任务无OOM并保留约1GiB独显余量。 |
| P4 首版交付 | 六类场景逐一完成正常/失败/取消路径；两款客户端可见正文通知自动分析；确认发送零次未经批准。完成SQLite迁移、隐私清理、本机MSIX安装/授权、登录恢复、重启、长期运行和回滚演示。 |

任何关键门槛未达到就暂停首版发布，提交失败样本和资源数据供重新确定范围或硬件要求。

## 7. P5–P6 后续研究

- P5：同任务集比较 Laya、Fara、Jev 风格策略、MiMo 与后续 Qwen 候选；发布后再研究 RSI。研究结果只能选预定义候选动作，权限始终由确定性 ToolBroker 裁定。
- P6：用户授权的脱敏轨迹、离线回放、影子策略、低风险试用与可回滚版本。禁止训练/在线更新改变权限。

Laya、Dream-RSI和Jev相关图表只能作为研究方向，不直接变成首版依赖，也不使用未授权云服务。
